## 1. 여덟 칸 — 5가 아니고 12도 아니다

위임이 경고한 대로 `dry` 한 줄은 서연과 승현이 **같이** 말한다. 그런데 그 둘은 말높임이 갈리므로
`register` 를 같이 걸면 **혼자가 된다.** 실제 조합을 세어 보면 다섯도 열둘도 아니라 여덟이다.

| 칸 | 조건 | 누가 보는가 | 이 칸의 목소리 |
|---|---|---|---|
| A | `humor: dry` + `register: casual` | **서연** 혼자 | 건조한 반말, `야` · `자냐`, 물음표 없는 평서문 |
| B | `humor: dry` + `register: polite` | **승현** 혼자 | 마침표 존댓말, 제안형(`들을게요`), ㅋ 0 |
| C | `humor: loud` | 하늘 · 소희 · 유나 | ㅋㅋ · 느낌표 · `야`, 아픈 말을 웃음으로 덮는다 |
| D | `humor: witty` + `register: casual` | **건우** 혼자 | 장난 먼저 진심 나중. `반칙`·`…농담이고` 는 안 쓴다(누수 상한) |
| E | `humor: witty` + `register: polite` | **지우** 혼자 | 변호사 존댓말. `변론` · `진술` · `정정해 주세요` |
| F | `humor: meme` | 민재 · 다은 | `[짤] ….jpg` 와 축약체. **ㅋ 금지**(다은 0%) |
| G | `humor: warm` + `register: casual` | 예은 · 정우 · **1위 없음** | 부드러운 반말. 정우의 `천천히 해.`·`하하` 는 안 쓴다(누수) |
| H | `humor: warm` + `register: polite` | **도윤** 혼자 | 트레이너 존댓말. `호흡` · `굳는다` · `-습니다` |

**혼자가 되는 칸이 넷(A·B·D·E·H 중 다섯)**이라 거기에는 캐릭터 고유 소재를 그대로 쓸 수 있었다.
`{char:<id>}` 도 루트 층도 필요 없었다 — 조건 두 개가 이미 한 사람을 가리킨다.

`1위 없음` 회차는 `warm`·`casual` 로 읽히므로(13_engine_fixes §1) **G 칸이 자동으로 그것까지 덮는다.**
그래서 G 는 "예은·정우용" 이 아니라 **기본 목소리**로 썼다 — 누구에게도 튀지 않아야 하는 칸이다.

**칸을 합칠 때의 함정 하나.** `loud` 와 `meme` 을 한 줄로 묶으면 ㅋㅋ 를 쓸 수밖에 없고, 그러면
**다은(ㅋ 0%)이 ㅋㅋ 를 쓴다.** 그래서 F 는 절대 다른 칸과 합치지 않았다. 같은 이유로 G 에도 ㅋ 이 없다
(정우는 r10 전 ㅋ 금지). 검사 스크립트가 이 두 규칙을 지킨다(§6).

## 3. 같은 비트, 두 목소리 — `m21` 과 `m26`

### 3.1 `m21` 고백 타이밍 (D+55) — 상대가 먼저 눈치채는 두 줄

**전**(전임의 중립 규약. 열두 명이 **글자 그대로 같은 두 줄**을 말한다):

```
(지문) 태현이 말했다. 고백은 확률이 70%를 넘을 때 하는 거라고.
상대: 아까부터 좀 조용한 것 같아서
상대: 무슨 할 말 있는 것 같던데
        ⏳ 15초
```

**후 — 1위가 서연일 때**(A 칸):

```
(지문) 태현이 말했다. 고백은 확률이 70%를 넘을 때 하는 거라고.
서연: 야
서연: 아까부터 말 아끼는 거 티 나
        ⏳ 15초
```

**후 — 1위가 지우일 때**(E 칸, 같은 비트·같은 박자):

```
(지문) 태현이 말했다. 고백은 확률이 70%를 넘을 때 하는 거라고.
지우: 아까부터 답이 한 박자 느려요.
지우: 변론 준비 중인 것 같은데, 상대가 저인가요?
        ⏳ 15초
```

`야` 한 글자와 `변론 준비 중인 것 같은데` 가 같은 자리에 온다. 서연은 `야` 로 말을 여는 사람이고
(NAME_GUIDE §4 "야 자냐"), 지우는 변호사다. **E 칸은 지우 혼자이므로 직업 소재를 써도 새지 않는다.**

나머지 여섯 칸도 같은 비트다: `야 뭐야 왜 조용해 ㅋㅋ`(C) · `아까부터 점 세 개만 보내는 사람 누구지 ㅋㅋ`(D) ·
`[짤] 할 말 있는데 못 하는 사람.jpg`(F) · `오늘 좀 조용하네`(G) · `오늘은 톡이 조용하시네요.`(H) ·
`아까부터 말이 줄었어요.`(B).

고백의 대답(C0 `critReply`)도 갈렸다 — 전임이 `지금 나올 수 있는지` 로 끊어야 했던 줄이
이제 **`지금 나올 수 있어?`** 와 **`지금 나오실 수 있어요?`** 다.

### 3.2 `m26` 첫 싸움 (D+64) — 싸움을 여는 한 줄

**전**(열두 명이 똑같이):

```
(지문) 자려고 누웠을 때 톡이 왔다.
상대: 요즘 관심 없는 것 같아서
나: 무슨 소리
```

**후 — 1위가 서연일 때**(A 칸):

```
(지문) 자려고 누웠을 때 톡이 왔다.
서연: 자냐. 요즘 나 뒷순위 같은데
나: 무슨 소리
서연: 어제 세 번 물어봤는데
서연: 답이 '나중에', '바빠서', '이따'
```

**후 — 1위가 도윤일 때**(H 칸):

```
(지문) 자려고 누웠을 때 톡이 왔다.
도윤: 요즘 제가 먼저만 보내는 것 같아요. 참으면 더 굳어서요
나: 무슨 소리예요
도윤: 어제 세 번 물어봤는데요
도윤: 답이 '나중에', '바빠서', '이따'
```

싸움을 여는 문장이 서연은 `자냐` 로 시작하고 도윤은 **근육이 굳는 비유**로 끝난다.
그리고 **플레이어의 되묻는 말도 함께 갈린다** — 이게 §6-3 이 요청한 것이다.

전임의 인용 기법(`답이 '나중에', '바빠서', '이따'`)은 그대로 뒀다. 인용문은 화자가 플레이어라
말높임이 개입하지 않으므로 **여덟 칸이 공유하는 것이 맞다.** 그 줄을 여덟 벌로 쓰면 낭비다.

## 4. 다섯 값이 너무 거친 자리, 그리고 반대로 갈라서는 안 되는 자리

### 4.1 `register` 가 `humor` 를 쪼개서 해결한 것 (§1 의 여덟 칸)

거칠다는 문제의 절반은 `register` 가 공짜로 풀었다. `dry` 둘 · `witty` 둘 · `warm` 셋이 각각 갈려서
**혼자 남는 칸이 다섯**이 됐고, 나머지 셋(C `loud` 3명 · F `meme` 2명 · G `warm·casual` 2명+없음)만
여럿이 나눠 쓴다. 이 셋은 **공통분모를 소재로 잡아** 썼다.

- C(하늘·소희·유나): 셋 다 ㅋ 밀도 30% 이상이고 `야` 로 부른다 → `야 … ㅋㅋ` 가 셋 모두의 실제 습관이다.
- F(민재·다은): 하나는 게임 반말, 하나는 마침표 존댓말→반말인데 **짤을 보내는 것만 같다** →
  이 칸은 문장을 쓰지 않고 `[짤] ….jpg` **한 장**으로 썼다. 말투가 갈리는 부분을 아예 비운 것이다.
- G(예은·정우·1위 없음): 셋 중 하나가 "사람이 아닌 경우" 라 **기본값 톤**으로 썼다.

### 4.2 갈라서는 안 되는 자리 — `m30` 권태는 일부러 `humor` 를 안 썼다

`m30` 의 `lines` 에는 `humor` 가 **하나도 없다.** `register` 만 썼다.
**열두 목소리가 `밥` 한 단어로 쪼그라든 것이 이 씬의 주제**이기 때문이다. 시끌한 하늘이 여기서
ㅋㅋ 를 쓰면 권태가 아니고, 짤을 보내면 대화가 살아 있는 것이 된다. 여기서 축을 쓰는 것은
기능이 있다고 쓰는 것이지 씬이 필요해서 쓰는 것이 아니다.

대신 **그 침묵이 깨지는 자리**(C0 "새로운 걸 제안한다")에서만 목소리가 돌아오고,
C2 "그냥 둔다" 의 한 글자만 `loud`(`ㅇ`)와 나머지(`.`)로 갈랐다.

### 4.3 `{char:<id>}` 도 루트 층도 쓰지 않았다

위임이 준 두 도피로를 쓸 일이 없었다. 한 사람을 가리키고 싶은 비트는 전부 A·B·D·E·H 칸에
들어갔고(§1), 그 칸들은 조건 두 개만으로 이미 혼자다.

## 5. 못 한 것 · 정직하게 남는 것

### 5.1 반응 묶음은 말높임 두 벌까지다 — 세 줄 상한 때문

`test/reply_coverage_test.dart` 의 `maxLines = 3` 은 **파일에 적힌 줄 수**를 센다(필터 뒤가 아니다).
그래서 한 반응 묶음에 쓸 수 있는 줄은 **세 개가 전부**다. 여덟 칸을 쓰면 여덟 줄이라 즉시 깨진다.

그래서 반응 묶음은 전부 이 형태다.

```
[ 조건 없는 줄 1개 ] + [ register: casual ] + [ register: polite ]     → 누구나 말풍선 2개
```

**결과: `humor` 51줄은 거의 전부 `lines` 에 있고, 반응 묶음은 `register` 126줄로 말높임만 갈린다.**
전임이 "5~7벌로 다시 쓰겠다" 고 한 것은 `lines` 에서만 지켰다. 반응까지 여덟 벌로 쓰려면
`maxLines` 를 올려야 하고 그건 내 파일이 아니다.

**대안으로 검토했다가 버린 것**: 세 줄을 `[loud+meme] [나머지 casual] [polite]` 로 쪼개면
목소리가 세 갈래로 갈리지만 **말풍선이 1개로 줄어든다.** 고백의 대답이 한 줄인 것보다
두 줄인 것이 낫다고 판단했다. `m30` C2 처럼 원래 한 줄인 비트에서만 이 방식을 썼다.

### 5.2 `m27` 의 사과 선택지는 두 벌로 못 쓴다 — 엔진 쪽 구멍 둘

§6-3 이 이름을 대며 요청한 `"미안했어. 내가 부족했어"` 는 **쪼갤 수 없다.** 두 가지가 동시에 막는다.

1. **`m27` 의 `hint` 가 0 이다.** `lib/engine/story_repository.dart:927` 의 lint 가
   `e.choices[h].isGated` 를 거부하고, `Choice.isGated` 는 이제 **`register` 까지 본다**
   (`models.dart:695` = `isPlayerGated || isVoiceGated`). 오류 문구는 여전히
   `hint 선택지에 MBTI 조건` 이라 원인을 감춘다. 실제로 이 실패를 봤다.
2. **그 선택지에 `minigame: reply_timing` 이 걸려 있다.** 두 벌은 `minigame` 도 글자 그대로 같아야
   하므로 자동으로 한 이벤트에 미니게임이 둘이 되고, `test/event_engine_test.dart`
   "한 이벤트에 미니게임은 최대 하나" 가 깨진다. 이것도 실제로 봤다.

둘 다 내 파일이 아니라 고칠 수 없다. 그래서 **문구를 행동 표기로 바꿨다**:
`"미안했어. 내가 부족했어"` → **`부족했다고 먼저 사과한다`**.
말높임이 드러나지 않으므로 지우·승현·도윤에게 반말을 쓰는 버그는 사라지지만,
**플레이어가 사과를 자기 말로 하는 대사 한 줄을 잃었다.** 이건 손실이고 숨기지 않는다.
(상대의 답은 두 벌 그대로다 — `말이 심했던 건 나도 마찬가지야` / `저도 마찬가지예요`.)

같은 이유로 **말높임 두 벌로 쪼갠 선택지는 넷뿐**이다: `m26` 의 T·F 전용 두 개와 `m27` 의 두 개.
`m21`·`m30`·`m36`·`m19`·`m17` 의 선택지는 전부 `지금 {top}한테 말한다` 처럼 **행동 표기**라
말높임이 애초에 드러나지 않는다. 억지로 쪼개지 않았다.

**다음 사람에게**: 엔진이 `hint` lint 를 `isPlayerGated` 로 좁히고,
"미니게임 최대 하나" 를 **필터 뒤 개수**로 세면 이 두 자리가 풀린다.

### 5.3 검증기는 내 데이터를 지키지 못한다 — 실험으로 확인했다

위임은 "커버리지가 강제된다" 고 했다. **내 데이터 모양에서는 강제되지 않는다.**
`StoryBundle.validate` 는 경우마다 **묶음 전체가 0줄**일 때만 거부하는데(`story_repository.dart:782`),
내 묶음에는 지문이나 조건 없는 줄이 하나씩 섞여 있어서 **절대 0줄이 되지 않는다.**

실제로 해 봤다. `m26` 의 `lines` 에서 **도윤 칸(H) 한 줄을 지우고** 전체 테스트를 돌렸다 —
도윤 1위 플레이어는 싸움을 여는 대사를 못 보게 되는데, **971개 전부 초록이었다.**
`1위 도윤(warm·polite) 플레이어에게 대사가 0줄` 은 나오지 않는다.

그래서 별도 점검을 썼다(`check_voices.py`, §6). 여기도 두 번 틀렸고 두 번 다 실험으로 잡았다.

| 시도 | 결과 |
|---|---|
| "경우마다 상대 말풍선 ≥ 1" | 도윤은 지운 뒤에도 공유 줄을 보므로 **못 잡는다** |
| "조건 붙은 줄이 잇따르는 구간마다 경우 전체가 덮이는지" | 서로 다른 박자의 조건 줄이 맞붙어 있어 한 구간으로 뭉쳐 **못 잡는다** |
| **"경우마다 말풍선 개수가 같은지"**(예외는 표에 명시) | **잡는다** — `m26.lines: 도윤 말풍선 수 (4, 1) ≠ 나머지 (5, 1)` |

**이 점검은 저장소에 없다.** `test/` 는 내 파일이 아니다. 다음 사람이 이 씬을 고치면
아무것도 막아 주지 않으므로, **검증기를 믿지 말고 §6 의 스크립트를 먼저 옮겨 심기를 권한다.**

### 5.4 아직 아무 목소리도 아닌 줄 — 22개, 그중 다섯 개는 진짜 문제다

조건을 안 쓴 상대 말풍선이 22개 남아 있다. 대부분은 남는 것이 옳다
(`…` 2개 · 인용문 `답이 '나중에', '바빠서', '이따'` · 한 단어 `아직` · `아 그래서`).
아래 다섯은 **읽어도 누구인지 모르겠는 줄**이고, 그렇게 남았다.

| 줄 | 어디 | 왜 문제인가 |
|---|---|---|
| `좋은데. 이건 약속으로` | `m26` C3 reply (두 벌 모두) | `약속으로` 로 끊는 사람은 실제로 없다. 전임의 중립 조각을 공유 슬롯에 그대로 뒀다 |
| `이런 건 어디서 알았는지` | `m30` C0 reply | §6-2 가 지적한 `-는지` 말버릇. 세 줄 상한 때문에 공유 슬롯이 필요해 살아남았다 |
| `그건 그거고. 밥 먹었는지부터` | `m27` C0 reply | 같은 `-는지` |
| `오늘은 답장 빠른데` · `이게 더 원래 모습 같고` · `이상한데` · `요즘 톡 재밌는데` · `근데 그건 누구한테 배운 건지` | `m17` 전부 | **일부러 원문을 한 글자도 안 바꿨다** — §5.5 |

### 5.5 `m17` 은 `register` 만 받았다 — 자유 입력 픽스처가 문구를 잠근다

`test/fixtures/free_input.json` 이 `m17` 을 쓰고, `free_input.dart` 의 `ChoiceSignature` 가
**`reply` 와 `critReply` 의 2-gram 을 서명에 넣는다.** 픽스처는 1위가 없는 상태(= `warm`·`casual`)로
돌기 때문에, 그쪽 문구를 한 글자라도 바꾸면 `top-1 ≥ 88%` 판정이 흔들린다.
그래서 `m17` 은 **casual 쪽을 원문 그대로 두고 polite 한 벌만 얹었다.** `failReply` 는 서명에 안
들어가므로 거기서만 실제 문장으로 고쳤다(`폰만 보고 있었는지` → `폰만 보고 있었어?` / `있었어요?`).
결과적으로 `m17` 의 casual 플레이어는 **전과 똑같은 화면**을 본다. 목소리 작업은 못 한 셈이다.

### 5.6 `m36` C2 "아무것도 하지 않는다" 는 손대지 않았다

침묵이 결과인 분기다(12_main_rewrite §6-4 와 같은 판단). `m04`(상대가 없는 독백)도 그대로다.

### 5.7 내 파일이 세션 중 **세 번** 되돌아갔다

`assets/story/characters.json` 과 `assets/story/events_main.json` 이 작업 중 각각 원본으로
되돌아갔다(파일 크기·mtime·`git diff` 로 확인). 다른 에이전트가 `assets/story/` 를 통째로 다시 쓰는
것으로 보인다. 그래서 두 변경을 **다시 실행 가능한 멱등 스크립트**로 만들어 두었고(§6),
최종 상태를 마지막에 다시 확인했다.

**병합 담당자에게**: 아래 세 줄과 `events_main.json` 의 클라이맥스 변경이 최종 트리에 실제로 남아
