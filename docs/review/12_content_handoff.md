## 1. `m01` — 이 게임의 첫 번째 선택이 이름 없는 사람에게 호감을 준다 ★


## 4. `test/**` — 숫자가 아니라 사실이 하나 바뀐다

내 변경으로 이벤트가 **늘거나 줄지 않았다**(107개 그대로). 그래서
`expect(baseEvents().length, 403)` 은 **내 쪽에서는 안 깨진다.** 위 §1 요청 A 를 받으면 404 가 된다.

바뀐 사실은 하나다. `sim_balance_test` 가 찍는 두 줄의 값이 달라진다(검사가 아니라 **출력**이다):

- `일상 중 반복(once:false) 비율` — 반복 가능 일상이 **25개 → 24개**가 됐다.
  다만 이 계수는 **반복 가능 이벤트를 처음 보는 것도 "반복"으로 센다**
  (`sim_balance_test.dart:774`). 그래서 44.1% → 47.1% 로 올라간다 — 재방송이 늘어난 게 아니다.
  진짜 재방송률을 찍는 계수가 저장소에 없다는 게 이 판의 문제다(`12_content_fixes.md` §1.5).
- `once 일상 미열람 …/56` (`sim_balance_test.dart:1240`) — 분모 `56` 이 문자열에 박혀 있다.
  값은 `b.events.where((e) => e.layer == daily && e.once)` 로 세는데(같은 파일 753행) **분모만 상수다.**
  내 변경 전에도 실제 값은 82 였으므로 **이미 틀린 라벨**이고, 이제 83 이 된다.
  분모도 `onceDaily.length` 에서 뽑게 해 달라.

| | 전 | 후 |
|---|---|---|
| 일상 총수 | 107 | **107** (안 늘렸다) |
| `once: false` (반복 가능) | 25 | **24** |
| `once: true` (1회) | 82 | **83** |

> 왜 25→24 로 한 개만 줄었나는 `12_content_fixes.md` §1 에 수치로 적었다.
> 요약: **반복 12개를 1회로 돌리는 동시에 11개를 반복으로 열었다.**
> 반복 풀을 그냥 5개로 줄이면 100일 후반에 같은 장면이 **2~3일 간격으로** 돌아온다 —

## 6. 엔진 요청 두 개 — 둘 다 이벤트를 안 늘리고 문제를 없앤다

이번 작업에서 **데이터만으로는 못 넘는 벽**을 두 개 만났다. 둘 다 `lib/engine/` 이라 내 파일이 아니다.

### 6.1 `{char:<id>}` 자리표시자 — `lib/engine/text_template.dart`

지금 `text_template.dart` 가 아는 것은 `{name}`(플레이어) · `{mbti}` · `{top}`(호감 1위) 셋뿐이다.
**특정 캐릭터를 가리키는 자리표시자가 없다.** 치환 자체는 이미 선택지 `text`
(`models.dart:603`)와 말풍선 머리 `name`(`models.dart:520`)에 다 걸려 있다 — **어휘만 없다.**

그래서 "선호에 따라 다른 한 사람"을 부르는 장면은 전부 **레코드를 쪼개야** 한다
(`m01`/`m01_m`, `m03`/`m03_m`, `m_brief`/`m_brief_m`, `m09`/`m09_f` …). 쪼갤 때마다
이벤트 수가 늘고 `expect(baseEvents().length, 403)` 을 손대야 한다.

```
{char:daeun}          다은
{char:daeun|이가}     다은이
{char:daeun||그 사람} 이름을 모를 때
```

조사·대체어 규칙은 `{top}` 과 똑같이 두면 된다 — `characters.json` 에서 이름을 읽어
`{top}` 과 같은 함수에 넘기는 것이 전부다. **선호 밖 캐릭터면 세 번째 칸(대체어)으로 내려가게** 하면
한 레코드가 양쪽 선호에서 다 맞는다:

```
[ ] {char:seoyeon||{char:jeongwoo}} 선배가 해 줬던 대로 한다
```

이게 있으면 지금 **덜 고친 채로 남아 있는 세 곳이 한 번에 닫힌다** —
`d_meet_05`(서연/정우) · `d_family_02`(예은/건우) · `m01`(다은/하늘, §1 요청 A 를 안 해도 된다).
이벤트 수는 안 늘어난다.

### 6.2 `StoryEvent.variants` — `lib/engine/models.dart`

판정문 §4-1 이 권고한 "재방송 상위 10개에 변형 지문"을 **데이터로는 못 한다.**
`lines` 가 고정 배열 하나뿐이라 변형을 담을 자리가 없고, 이벤트를 복제하면 id 와 개수가 늘어난다.

`12_content_fixes.md` §1.2·§1.5 가 수치로 보이는 결론이 이것이다:
**100일 동안 일상 슬롯이 뽑는 횟수(`D`)가 뽑힐 수 있는 서로 다른 일상 수(`A`)보다 크고,
`once` 를 어디에 붙여도 `D − A` 는 안 변한다.** 실측으로 D+80 이후에는 조건을 통과하는
`once` 일상이 **0개**라 후반 20일의 일상은 전부 반복 풀에서 나온다(기준선도 같다).

그래서 재방송 비율 23~25% 를 실제로 내리는 길은 둘뿐이다.

| | 비용 | 효과 |
|---|---|---|
| (a) 일상을 40~60개 더 쓴다 | 새 글. `403` 테스트 갱신 | `A` 가 올라가 비율이 내려간다 |
| (b) `StoryEvent` 에 `variants` 를 붙인다 | 엔진 작업 1건 | **글 한 편으로 2~3회분을 덮는다.** id·개수 불변 |

(b) 의 최소 형태는 "n번째로 뽑혔을 때 `lines` 대신 쓸 대체 배열"이다:

```json
"variants": [
 [ {"who":"narr","text":"또 엘리베이터. 이번엔 눈이 먼저 마주쳤다."}, … ],
 [ {"who":"narr","text":"세 번째다. 이제 층수는 안 물어봐도 된다."}, … ]
]
```
