## 0. 먼저 — 숫자가 안 내려갔다. 왜인지부터 적는다

지시서의 목표는 재방송 비율 21.0% 를 내리는 것이었다. `test/rerun_share_test.dart` 로 다시 재면
**21.0% → 21.8%** 다. **안 내려갔고, 0.8%p 올라갔다.** 문턱을 만지거나 측정을 바꿔서 가리지 않았다.

이유는 하나다. **그 테스트는 이벤트 `id` 로만 센다.**

```dart
// test/rerun_share_test.dart, RerunTally.saw
void saw(StoryEvent e) {
  final n = (count[e.id] ?? 0) + 1;   // ← id
```

`playFullRun` 이 큐에서 꺼내는 것은 `engine.viewFor(s, ev)` 이고, `viewFor` 는 변형 대사를 골라
넣어도 **id 를 바꾸지 않는다**(`StoryEvent.withLines` 가 id 를 복사한다). 그래서
**12_engine_fixes §4.1 이 재방송을 줄이라고 만들어 준 `variants` 는 이 테스트에 한 글자도 안 보인다.**
엔진 쪽 문서가 "실효 +20" 이라고 쓴 그 '실효' 가 정확히 이 눈금 밖이다.

그래서 같은 정의(`(읽은 씬 − 서로 다른 씬) / 읽은 씬`)를 **씬 식별자만 `id` 에서 `id#변형번호`로
바꿔** 다시 쟀다. 변형 고르는 식은 `EventEngine.variantOf` 를 그대로 옮겼다
(`tool/unseen_dailies.dart`, 시드 5 × 선호 2 × 전략 3 = **100일 완주 30회차**).

| 지표 (30회차 실측) | 작업 전 | 과제 1·2 뒤 | 최종(과제 3까지) |
|---|---|---|---|
| **재방송 — 플레이어가 읽는 글자 기준** | **21.7 %** | **4.5 %** | **4.8 %** |
| 재방송 — `id` 기준(테스트와 같은 눈금) | 21.7 % | 20.7 % | 21.8 % |
| `rerun_share_test` 6회차, `id` 기준 | 21.0 % | 21.2 % | **21.8 %** |
| 회차당 안 읽힌 1회성 일상 | 31.7 / 101 | 28.4 | 29.1 |
| 회차당 읽은 씬 | 272 | 274 | 276 |

읽는 사람이 판단할 수 있게 두 줄로 말한다.

- **같은 글자를 다시 읽는 비율은 21.7% → 4.8% 로 내려갔다.** 반복 가능한 일상 24개 전부와
  새로 쓴 뒷일 장면 10개에 변형 대사를 달았기 때문이다(§2).
- **`id` 기준 숫자는 21.8% 로 제자리다.** 과제 1·2 만으로는 20.7% 까지 내려갔는데(−1.0%p),
  과제 3 이 **회차당 7.5개의 새 장면**(미니게임을 져야 열리는 뒷일)을 더하면서 그중 3~4개가
  같은 id 의 재등장으로 세어져 +1.1%p 를 되돌려 놓았다. 그 3~4개는 **글자가 다르다**(변형).
- 6회차 표본(`rerun_share_test`)과 30회차 표본이 0.5~1%p 씩 엇갈린다. 6회차는 이 효과 크기에
  비해 표본이 작다 — 30회차 숫자를 믿는 게 맞고, 두 숫자를 다 적어 둔다.

**요청**: `RerunTally` 가 `(id, 변형번호)` 로 세게 해 주면 이 눈금이 목표를 실제로 측정한다.
한 줄이고 계산식은 내 하네스에 있다 → `13_content_handoff.md` §2.

## 1. 과제 1 — 안 열리던 트리거를 풀었다

### 1.1 먼저 만든 것: 이벤트 하나씩 세는 진단 (`tool/unseen_dailies.dart`)

"34.8개가 안 읽힌다"는 총량만으로는 무엇을 고칠지 모른다. 그래서 100일 완주 30회차를 돌리면서
일상 이벤트마다 **① 후보(`candidates(daily)`)로 한 번이라도 올라왔나 ② 실제로 읽혔나** 를 세고,
후보가 못 된 이벤트에는 **트리거 조항을 하나씩 떼어 보며 "이 조항만 없으면 열렸을 날"** 을 같이
찍게 했다. 범인을 눈으로 지목하는 표다.

첫 실측:

```
회차당 안 읽힌 once 일상 평균 31.7 / 101
회차당 — 후보조차 못 됨 26.9 · 후보는 됐는데 안 뽑힘 4.8
```

**31.7 중 26.9 는 추첨 운이 아니다.** 트리거가 안 열린 것이다. 그 26.9를 네 갈래로 갈랐다.

| 갈래 | 개수(회차당) | 판단 |
|---|---|---|
| (가) 설계상 당연 — 선호 반대쪽 쌍 7개, 이 회차에 없는 캐릭터의 `*_mbti_talk` 6개, 내기 정산 3종 중 안 고른 2개 | ~15 | **열면 안 된다** |
| (나) 2회차 전용 — `yuna_mbti_talk`(히든 유나 루트가 `run: [2,99]`) | 1 | **1회차 측정에 안 잡히는 게 맞다** |
| (다) 테스트가 못 박은 설계 — 오프닝 10개의 `day: [1,3]`, 후속 3개의 `day: [4,20]` | ~5 | **넓혔다가 되돌렸다** (§1.3) |
| (라) **그냥 막혀 있던 것** | ~6 | **열었다** (§1.2) |

### 1.2 연 것 — 이벤트 7개, 장면 4개가 사실상 죽어 있었다

`tool/open_triggers.py`. 값이 정확히 일치할 때만 바꾸고 하나라도 안 맞으면 파일을 안 쓴다.

**(a) 픽업 영상 3연작이 통째로 죽어 있었다 — 도달 불가능한 스탯 조건.**

입구인 `d_temp_01`(픽업 영상 알고리즘)이 `esteem [0, 35]` 를 요구한다. 그런데 D+20 이후
자존감 분포를 실측하면(30회차 × 80일)

```
esteem  p05=62  p25=98  p50=100      ← [0,35] 은 하위 5% 밑이다
```

**자존감 35 이하는 D+20 이후에 사실상 없다.** 실측 후보 2/30 회차. 그래서 `d_temp_01` 이 세우는
`pickup_1` 도 거의 안 서고, 그걸 요구하는 `d_temp_02`(weight **8**)·`d_temp_06`(weight **6**)까지
**세 장면이 한 묶음으로 죽어 있었다.** 가중치 17을 들고 아무도 못 보는 자리에 서 있던 것이다.

조건을 **없앴다**(`{"day": [18, 100]}`). 알고리즘은 자존감을 보고 영상을 밀지 않는다. 그리고
선택 설계로도 거꾸로였다 — **"자존감이 이미 낮은 사람에게만 유혹을 보여 준다"** 면, 아직 안
넘어간 사람에게는 유혹이 없다. 유혹은 넘어갈 수 있는 사람에게 와야 선택이 된다.

### 1.3 넓혔다가 **되돌린 것** — 테스트가 지키는 설계다

**오프닝 일상 10개(`d_open_*`)가 사흘을 두고 경쟁한다.** 전부 `day: [1, 3]` 이고, 오프닝 사흘이
뽑는 일상 칸은 예닐곱 개다. 그래서 **회차마다 서너 개는 구조적으로 못 나온다**
(실측: `d_open_groupchat` 6/30, `d_open_story`·`d_open_outfit`·`d_open_late_msg` 각 12/30).

창을 넓혀 봤다 — 픽션이 D+1 에 안 묶인 넷은 그대로(`잘못 온 문자`·`위로 짤`·`새벽 1시 14분`·
`단톡 자기소개`), 묶인 셋은 그 말 한 줄만 고쳐서(`프사 바꾼 김에` → `스토리를 하나 올렸다`,
`100일 프로젝트 첫 외출` → `사람을 만나러 나가는 날`, `프사를 바꾼 지 한 시간` → `프사를 바꾼 뒤로 처음`).
`d_fu_*` 셋의 창도 `[4,20]` → `[4,100]` 으로 열었다.

**실측 효과는 분명했다.** "후보는 됐는데 안 뽑힘" 이 **4.8 → 1.7** 로, 안 읽힌 것이
**31.7 → 25.8** 로 떨어졌다(지금 도달한 28.4보다 2.6개 더).

그런데 `test/opening_test.dart` 가 이걸 셋으로 막는다.

```
일상 오프닝은 day [1, 3~4]·weight 3~5          → day.max ∈ [3,4]
일상 오프닝(2단 포함)은 4일차부터 후보에 들지 않는다   → 4~100일차 전부에서 후보 0
4일차 이후 기존 풀 잠식 없음: 10일차 일상 후보 수가 오프닝 추가 전과 같다
오프닝 플래그 후속은 … 4~20일차에 열린다          → trigger.flags == [flag], day.max ≤ 20
```

세 번째 줄의 이름이 답이다 — **"기존 풀 잠식 없음"**. 오프닝은 첫인상 묶음이고 중반 풀을
희석하지 않는다는 것이 **결정**이지 누락이 아니다. 내 파일이 아닌 테스트가 그 결정을 지키고
있으므로 **전부 되돌렸다**(대사 세 줄도 함께). 실측한 이득과 맞바꿀 것의 목록을
`13_content_handoff.md` §1 에 숫자로 넘긴다 — 판단은 그 설계를 정한 쪽이 해야 한다.

### 1.4 열지 않은 것과 그 이유

- **`d_fu_lurker`(0/30)** — `lurker` 는 `d_open_groupchat` 의 '읽기만 한다'를 골라야 선다.
  **선택지 조건은 안 풀었다.** 눈팅을 안 한 사람을 눈팅했다고 호명할 수는 없다. 이건 갈래의
  보상이고, 그 갈래를 고르지 않은 회차에서 안 열리는 게 맞다. 내 시뮬레이션 전략 셋이 전부
  이 선택지를 안 골라서 0/30 으로 찍힌다 — **도달 불가가 아니라 측정 하네스의 한계다.**

  쓴 장면이고, 한 명만 파는 회차에서 다른 사람의 반전이 안 열리는 것이 설계다. **문턱을 내려서
  숫자를 만들지 않았다.**
- **`d_two_01`~`05`** (`anyAffection` 두 명) — 양다리 실을 위한 조건이다. 같은 이유로 안 만졌다.
- **`d_date_04` 예산 초과** — 반복 풀 깊이를 위해 `money [0,160]` 으로 넓혔다가 **되돌렸다.**
  200시드 실측에서 D+100 잔고 288 → 260, `c_money_fight` 101 → 118 로 움직였다. 후보 3회차를
  얻는 대가로 경제를 건드리는 거래는 안 받는다(`tool/stop_reruns.py` §1.4 가 같은 실수를
  기록해 뒀다 — 그 기록을 읽어서 안 반복했다).

## 2. 과제 2 — 변형 대사 **68벌** (이벤트 34개)

`tool/write_variants.py` (반복 일상 24개 × 2벌 = 48) + `tool/fail_consequences.py`
(뒷일 장면 10개 × 2벌 = 20).

**상위 10개가 아니라 반복 가능한 일상 24개 전부에 달았다.** 이유는 산수다. 100일 회차에서 일상
칸은 약 152번 뽑는데 그 회차에 낼 수 있는 일상은 99종뿐이다. 차이 53번을 **지금은 그 24개가
전부 받는다** — 한 장면을 회차당 4~5번 읽는다. 상위 10개만 덮으면 나머지 14개가 여전히 맨몸으로
그 차이를 받는다. 24개 전부에 원본 + 변형 2벌 = **3벌**을 주면 반복 풀이 실효 72종이 되고,
`EventEngine.variantOf` 의 회전이 **세 번째로 볼 때까지 글자가 안 겹치는** 것을 보장한다.

지킨 것:

- **`once: false` 에만 달았다.** `once: true` 는 검증기가 막는다(한 회차에 한 번뿐이라 낭비).
- **사진 줄 유무를 원본과 맞췄다.** `isMoment` 판정이 회차마다 흔들리면 하루 계획 가중치가 흔들린다.
  24개 다 원본에 사진 줄이 없어 변형에도 없다. 뒷일 장면은 사진이 있는 쪽은 변형에도 넣었다.
- **선택지로 이어지는 전제를 깨지 않았다.** 변형은 대사만 바꾸므로 **같은 선택지 세 개로
  이어지는 다른 도입부**여야 한다. 예: `d_kakao_05` 의 세 번째 선택지가 `"ㅋㅋ 아니고 ㅠㅠ 였어"`
  이므로 변형 둘 다 'ㅋㅋ 오타가 나갔다'까지 반드시 간다. `d_date_07` 의 `다른 노래에 도전한다`
  는 '부를 줄 아는 노래가 하나뿐'이라는 전제를 요구하므로 변형 둘 다 그 줄을 다르게 말한다.
- **`sys wait` 줄과 말하는 사람 구성을 유지했다.** `d_kakao_03` 은 `narr → them(시스템 문구) →
  wait → narr` 이고 변형도 같은 뼈대다. `d_drink_05`·`d_work_01`·`d_misc_02`·`d_luck_04` 처럼
  상대의 톡으로 시작하는 것은 변형도 그 사람의 톡으로 시작한다.

한 예:

```
d_misc_04 혼밥  (선택지: 그냥 먹는다 / {top}한테 연락한다 / 요리를 해본다)
원본  저녁 8시. 혼자 먹는 게 익숙해졌다. / 익숙해진 게 좋은 건지는 모르겠다.
변형1 편의점 도시락. 계산대에서 젓가락을 두 개 받았다. 한 개면 됐는데. / 익숙한 실수다.
변형2 식당에 혼자 앉았다. 4인석이다. 다른 자리가 없었다. / 밥이 나오기 전까지 볼 게 폰밖에 없다.
```

세 벌 다 "혼자 먹는 저녁"이고, 세 선택지 전부가 그대로 말이 된다. 그리고 세 벌이 **같은 감정의
다른 증거**다 — 익숙함(원본), 몸에 남은 습관(변형1), 자리 크기(변형2).

## 4. 못 한 것 · 위험

1. **`rerun_share_test` 의 21.0% → 21.8% 을 못 내렸다.** 내려간 것은 같은 정의를 변형까지
   세는 눈금(21.7% → 4.8%)이다. 두 숫자가 갈리는 이유는 §0 이고, 눈금을 고치는 한 줄 요청을
   핸드오프 §2 에 적었다. **문턱값을 만지지 않았고 측정을 바꿔서 통과시키지도 않았다.**
2. **오프닝 10개의 구조적 손실(회차당 3~4개)을 못 풀었다.** 실측한 이득과 함께 핸드오프 §1 로
   넘겼다 — `test/opening_test.dart` 가 지키는 설계 결정이라 콘텐츠가 혼자 정할 일이 아니다.
3. **`repeatableDaily` 가 24 → 34 로 읽힌다.** §3.1 에 이유와 요청. 방지선 하한은 14 라 지금은
   위험하지 않지만 **계수가 실제보다 넉넉해 보인다.**
4. **`events_main.json` 의 미니게임 선택지 24곳에 `failNext` 가 없다.** 내 파일이 아니다.
   붙일 자리와 쓸 뒷일 장면 id 를 핸드오프 §3 에 표로 적었다.
5. **`d_fu_lurker` 는 여전히 30회차에서 0번 읽힌다.** 열 수 있는 상태인데 내 시뮬레이션 전략
   셋(첫 선택지·호감 최대·한 명 집중)이 '읽기만 한다'를 아무도 안 고른다. **선택 갈래의
   보상이므로 조건을 풀지 않았다**(§1.4). 실기기 플레이테스트에서 확인할 항목이다.
6. **`signals.json` 은 안 건드렸다.** 이번 지시에 해당 항목이 없었다.
7. **커밋하지 않았다.**
