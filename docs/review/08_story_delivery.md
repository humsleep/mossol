# 08. 스토리 전달 감사 — "무슨 스토리인지 이해가 안 간다"의 원인

> 2026-09-26 · game-designer. **코드·데이터는 한 줄도 고치지 않았다.** 이 문서만 쓴다.
> 대상은 이야기의 *내용*이 아니라 **플레이어가 볼 것을 고르고 액자에 끼우는 시스템**이다
> (`planDay`, 레이어 가중치, 트리거 게이트, 날짜 카드·정산·홈의 문구).
> 근거: (1) `assets/story/*.json` 447개 이벤트를 스크립트로 전수 집계, (2) `lib/engine/event_engine.dart`·
> `lib/game_controller.dart`·`lib/ui/*.dart` 의 현재 구현, (3) **이 프로젝트의 자체 시뮬레이터 출력**
> `tool/sim_out/sim_balance_report.txt`(200시드 × 11전략, 선호 f), (4) `test/opening_test.dart`·
> `test/route_order_test.dart` 가 실제로 고정하는 것.
> 선행 감사: `docs/review/03_game_design.md` §1·§7(첫날이 지문으로 시작한다 / 벤치마크는 1분 안에 전제를 말한다).

## 0. 한 줄 판정

**관통선은 데이터에는 있고 화면에는 거의 없다.** 메인 플롯은 플레이어가 읽는 것의 **14.5%**(글자 수로 17%)이고
**100일 중 58일은 플롯이 0개**이며, 그 플롯의 **31%(55개 중 17개)는 `them` 대사가 한 줄도 없는 순수 지문**이고
클라이맥스(고백·첫 싸움·마지막 선택)는 **상대의 이름을 한 번도 부르지 않는다**. 반대로 화면의 58%를 차지하는
일상 층은 **3분의 1이 문맥이 0**이다. 개발자가 "무슨 스토리인지 모르겠다"고 느낀 것은 취향이 아니라 **배합비**다.
**결론: 지금 구조로는 이야기를 실을 수 없다. 첫 7일은 각본으로 고정해야 하고, 그건 데이터만으로는 불가능하다
(§7.3).**

## 1. 관통선이 있는가 — 숫자

### 1.1 메인 층은 무엇을 하기로 되어 있나

`events_main.json` 55개는 유일하게 **보장된** 층이다. `EventEngine.planDay` 첫 블록:

```dart
for (final e in candidates(s, EventLayer.main)) { add(e); }   // 가중치 추첨이 아니다 — 전부 넣는다
```

그리고 `StoryBundle.validate`: `main 이벤트는 day 가 필요` + `main 날짜 중복` 금지. 즉 메인은
**날짜 고정 · 트리거 없음 · 100% 발생**이다. 전수 확인: 55개 중 `trigger` 에 `pref` 외의 조건이 붙은 것은 **0개**.

### 1.2 실제로 몇 개를 보고, 며칠에 터지나 (계산)

55개 중 13쌍(26개)이 선호별 쌍둥이(`m03`/`m03_m` 등)이고 29개가 공용 → **한 회차에 42개**.
42개가 터지는 날(f·m 동일):

```
1, 2, 4, 5, 8, 11, 14, 17, 20, 23, 26, 29, 32, 35, 37, 39, 40, 43, 44, 46, 49, 52,
55, 57, 59, 60, 61, 64, 67, 70, 73, 76, 78, 80, 83, 86, 89, 92, 95, 97, 99, 100
```

- **플롯이 있는 날 42일 / 없는 날 58일.**
- 첫 주만 보면 D1·D2·D4·D5 뿐 — **D3·D6·D7은 플롯이 0개**다.
- D5 이후는 사실상 3일에 1개(8→11→14→17…). 하트 경제상 하루 1세션이면 **플롯은 3일에 한 번**이다.

### 1.3 하루에 무엇이 몇 개 오는가 (`planDay` 순서)

1. 메인 전부(사실상 0개 또는 1개)
2. 위기 후보가 있으면 가중치 1위, 없으면 **일상 1개 가중치 추첨**
3. **루트 1개** (`_pickRoute`: 오프닝 1~3일차는 균등, 4일차부터 호감 1위)
4. 히든 30% 확률로 1개
5. 목표치까지 일상으로 채움 — 평소 `minEventsPerDay = 3`(보정 1개까지), 1~3일차는 `openingMinEventsPerDay = 4`

시뮬레이터 실측(`sim_balance_report.txt` `[f]`, 선호 f):

| 항목 | first | maxAff | focus |
|---|---|---|---|
| 하루 평균 이벤트 | **2.9** | 2.9 | 2.9 |
| 루트 이벤트/회차 (합) | 66.3 | 69.7 | 74.6 |
| 히든/회차 | 2.69 | 3.42 | 2.71 |
| 위기 일수/회차 | 5.5 | — | — |

→ 회차당 총 **약 290개**. 메인 42개는 고정이므로:

| 층 | 회차당 개수 | 비중 | 글자 수(평균 자/이벤트) | 읽는 글자 비중 |
|---|---|---|---|---|
| **main (플롯)** | **42** | **14.5%** | 300 → 12,600자 | **17.1%** |
| route | 66~75 | 24% | 294 → 20,600자 | 28% |
| **daily** | **약 169** | **58%** | 229 → 38,700자 | **53%** |
| crisis | 5.5 | 2% | 214 | 1.6% |
| hidden | 2.7~3.4 | 1% | 204 | 0.8% |

호감 이동으로 봐도 같다 — `[j] 호감 공급`: route 169~359, **main 31~56**, daily 46~97.
**메인 플롯은 관계 변화의 8~13%만 만든다.**

### 1.4 그런데 그 14%가 메신저 게임처럼 오지 않는다 (가장 아픈 수치)

대사 줄의 화자 분포(전수):

| 층 | 총 줄 | `narr` | `them` | `sys` | `me` | 첫 줄이 `them` |
|---|---|---|---|---|---|---|
| **main** | 315 | **45%** | **38%** | 12% | 6% | **33%** |
| route | 1,299 | 19% | **62%** | 12% | 8% | **58%** |
| daily | 477 | 37% | 55% | 4% | 4% | 24% |
| crisis | 41 | 78% | 12% | 10% | 0% | 6% |
| hidden | 50 | 66% | 24% | 10% | 0% | 12% |

- **메인 55개 중 17개(31%)는 `them` 대사가 한 줄도 없다**: `m01 m04 m11 m17 m18 m18_m m19 m21 m22
  m23 m26 m27 m28 m30 m31 m36 m39`. 그중 **16개는 100% 지문**이다.
- D1 `m01` 첫 줄: `sys: "100일 프로젝트 첫날. 태현이 말했다. \"일단 프사부터 바꿔.\""`
  → 인트로 화면에서 태현이 방금 **문자로** 말을 걸어 놓고, 게임 첫 이벤트가 그 태현을 **3인칭으로 전한다**.
  03 §8 #2가 지적한 그대로이고 아직 안 고쳐졌다.
- D8 `m04`(거울 앞에서)는 **6줄 전부 `narr`** — 등장인물이 없다.
- 후반 척추가 전부 여기 들어 있다: `m21 고백 타이밍`, `m22 라이벌 등장`, `m26 첫 싸움`,
  `m27 화해`, `m30 권태`, `m31 재회`, `m36 마지막 선택`, `m39 마지막 밤`.

### 1.5 그 척추는 상대의 이름을 부르지 않는다

메인 55개 중 `@top`(지금 호감 1위)으로 효과를 주는 것 9개. 실제 대사:

- `m22`(57일): `narr: "상대의 SNS에 모르는 사람이 나온다."` → **"상대"**
- `m26`(64일): `narr: "요즘 나한테 관심 없는 것 같다는 톡이 왔다."` → **누가 보냈는지 없음**
- `m21`(55일) 선택지 `지금 한다` → `affection {"@top": 8}` → **누구에게 고백하는지 화면에 안 나온다**
- `m36`(92일): `narr: "8일 남았다. 지금 상태로 끝낼 수도…"` → 상대 없음

원인은 엔진에 있다. `lib/engine/text_template.dart` 의 자리표시자는 `{name}`(플레이어)과 `{mbti}` **둘뿐**이다.
**"지금 호감 1위의 이름"을 대사에 넣을 방법이 존재하지 않는다.** 그래서 작가가 익명으로 쓸 수밖에 없었고,
그 결과 100일 서사의 클라이맥스 8개가 "그 사람"과의 사건이 되었다. 이야기가 사람에 붙지 않는 근본 원인이다.

### 1.6 하루를 닫는 문장도 플롯 것이 아니다

`game_controller.dart:1391`

```dart
if (ev.cliffhanger != null) cliffhanger = ev.cliffhanger;   // 마지막에 덮어쓴 것이 이긴다
```

`planDay` 순서가 **메인 → 일상 → 루트 → 히든 → 채우기 일상**이므로, 메인이 있는 날에도 **뒤에 오는
루트·히든·일상이 클리프행어를 가지고 있으면 플롯의 마지막 줄이 지워진다.**

| 층 | 클리프행어 보유 |
|---|---|
| main | 33/55 (60%) |
| route | 108/237 (46%) |
| daily | 20/123 (16%) |
| crisis | **0/16** |
| hidden | 2/16 |

루트가 46%니까 **메인 날의 절반 가까이에서 플롯의 클리프행어가 루트 것으로 바뀐다.**
그리고 D2 `m02`·D4 `m_mbti_chat` 은 클리프행어가 **아예 없다** → 이 이틀은 플롯이 다음 날로 아무 실도 넘기지 않는다.

**§1 결론**: 관통선은 42개 · 14.5% · 58일 공백 · 31%가 지문 · 후반 척추 8개가 익명 · 절반의 마지막 줄이 덮임.
이야기가 이해되지 않는 것이 정상이다.

## 2. 플레이어는 "이 사람이 누구인지" 듣는가

### 2.1 캐스트 소개는 **첫 회차에서 도달 불가능하다** (가장 큰 단일 결함)

추적:

- `lib/main.dart:236` — `Phase.home when controller.shouldShowIntro => IntroScreen(...)`
- `game_controller.dart:771` — `shouldShowIntro = !introSeen && !hasSave && totalRuns == 0`
- `intro_screen.dart:_finish → _start` — 마지막 답 뒤 곧바로 `await c.newGame(preference: preference)`.
  주석에도 명시: *"여기서 홈을 거치지 않는다 — 인트로 다음 화면은 D+1 날짜 카드다."*
- `PreferenceScreen`("**이 사람들을 만나게 돼요**", 5명 × 아바타·이름·역할·한 줄 매력·첫 메시지 말풍선,
  히든은 `???`)을 띄우는 곳은 **`home_screen.dart:328 _startNewGame → OnboardingGenderScreen.run` 뿐**이다.

⇒ **처음 켠 사람은 캐스트 소개를 보지 않는다. 2회차부터 본다.**
`characters.json` 의 12개 tagline(`단톡에서 나만 콕 집은 선배`, `영수증 뒷면에 나를 그린 선임`,
`말없이 전학 간 짝꿍이 돌아왔다` …)은 잘 쓰인 소개문인데 **첫 판에서는 죽은 데이터**다.
`docs/review/evidence/07_cast_intro.png` 는 지금 첫 실행 경로에 없는 화면이다.

### 2.2 전제("이게 무슨 게임인가")도 확률에 맡겨져 있다

인트로(`intro_screen.dart`)가 말하는 전부: `야` / **`100일 프로젝트, 진짜 할 거야?`** / `오늘부터 D+1이다`.
**"100일 안에 연애한다"를 말하는 문장이 없다.** 그 문장이 있는 곳은 일상 이벤트
`d_open_bet`("100일 안에 연애 못 하면 네가 치킨 열 마리") 하나이고, 이것은 `weight 5`, `day [1,3]`,
같은 창의 후보 10개(가중치 합 38) 중 **7칸을 추첨**으로 가져간다.
몬테카를로 20만 회: **d_open_bet 이 첫 3일에 등장할 확률 80%** → **5명 중 1명은 전제를 못 듣고 첫 세션을 끝낸다.**

### 2.3 r00("이렇게 만났다")은 보장되지 않는다 — 테스트가 보장하는 것의 정확한 범위

`docs/ROUTE_ORDER.md` 와 `test/route_order_test.dart` 가 실제로 고정하는 것:

```dart
('seoyeon_r02', 'seoyeon_r00|seoyeon_r01'),   // r00 "또는" r01
```

즉 **루트 이벤트끼리의 선후**만 보장하고, **r00 이 그 캐릭터와의 첫 접촉보다 먼저 온다는 보장은 없다.**
`ROUTE_ORDER.md` 가 직접 그렇게 적어 놓았다: *"결과적으로 r00은 선택적 장면이 된다. 호감이 먼저 16을 넘으면
r01이 첫 접촉이 된다."*

`test/opening_test.dart` 가 고정하는 것: **1·2일차 루트는 `_r00` 이고 같은 r00 이 이틀 연속 나오지 않는다.**
선호별 r00 은 4개(`f`: `seoyeon_r00 yeeun_r00 daeun_r00 sohee_r00` / `m`: `haneul_r00 minjae_r00
jeongwoo_r00 geonwoo_r00`).

⇒ **한 회차에 4명 중 2명만 "이렇게 만났다" 장면을 받는다.** 남은 2명은 3일차부터 `r01` 이
첫 등장이 된다(`seoyeon_r01` 트리거: `day [3,100]`, `affection * [0,100]`, 플래그 요구 **없음**).

그 r01 이 소개를 하지 않는다:

| 이벤트 | 첫 줄 | 소개하나? |
|---|---|---|
| `seoyeon_r00` | `@{name} 너 지난주에 강의실 앞에서 나한테 길 물어봤던 사람 맞지?` | ○ (첫 접촉) |
| **`seoyeon_r01`** | **`너 이번 주 모임 오지?`** | **× 이름·관계·역할 0** |
| `yeeun_r00` | `혹시 너 우리 초등학교 6학년 3반 … 나 예은이. 옆자리.` | ○ |
| `yeeun_r01` | `narr: 초등학교 동창회. 6학년 때 옆자리였던 예은이 먼저 알아봤다.` | △ (지문) |
| `sohee_r01` | `드래곤 ㄱㄱ!! 탑 빠져!` | × 이름 없음 |

화면도 돕지 않는다. `event_screen.dart:749` 헤더 상태줄은
**`온라인` / `자리 비움` / `부재중` / `온라인 · N명`** — **역할도, 관계 단계도 없다**(03 §7, 벤치마크 §2 #3 미구현).
`grep`으로 확인: `아는 사이|썸|거의 연인` 문자열은 `lib/` 어디에도 없다.

### 2.4 "서연이 누구인지" 말하는 줄은 **14일차**에 온다

`m06`(14일차, 첫 디엠) 첫 줄: `narr: "SNS 팔로우 요청이 왔다. **동아리 선배 서연**."`
= 게임에서 서연의 정체를 말하는 유일한 문장. 그런데 그녀는 **1~3일차부터 톡을 보내 왔다.**
`ROUTE_ORDER.md §판단이 애매해 남긴 것` 이 이 모순을 인정하고 그대로 두었다("고치려면 m06 대사를 손봐야 한다").
예은/`m08`(20일차, 준호가 "지난주 동창회에 예은이 왔더라")도 같은 문제로 남겨 두었다.

### 2.5 조연은 소개가 아예 없다

- **태현** — 인트로 화면에서만 소개된다(문자 보내는 친구). 인트로를 건너뛴 2회차 이후에는 소개가 0.
- **준호** — 첫 등장이 **11일차 `m05`**("야 우리 둘 다 이대로면 서른 돼도 이러고 있다"). 누구인지 설명 없음.
  그런데 `pact` 플래그는 시뮬 100% 발생 = 모든 회차의 축인데, 정작 `pact` 를 요구하는 이벤트는 **0개**다
  (grep 확인) — 협약이 세워지지만 아무것도 잠금해제하지 않는다.
- **히든(도윤·유나)** — `doyun_r01`/`yuna_r01` 트리거는 `day [5,100] + stats.charm [40,100]` 뿐.
  소개 비트가 존재하지 않고, 캐스트 소개에서도 `???` 다(설계 의도).

### 2.6 보너스: "형식 파괴"(모먼트)는 첫 주에 0개다

전 모먼트 30개의 호감 게이트를 전수 확인했다. 캐릭터 모먼트의 **최저 게이트는 `affection [10,35]`** 이다
(`mo_seoyeon_photo_night` day 4+, `mo_minjae_photo_ramen` day 5+, …).
시뮬레이터 `[early]`: **D10 마감 최고 호감 med 8** (D3 은 med 2).
⇒ **첫 캐릭터 전화·사진은 실제로 D18~26쯤 온다.** 첫 주에 쓸 수 있는 모먼트는

## 7. 첫 7일 각본 제안

### 7.1 설계 목표 (7일 안에 반드시 서야 하는 것)

1. **전제**: "100일 안에 연애한다"를 **사람이 문자로** 말한다 (확률 아님)
2. **판돈**: 실패의 대가가 있다 (치킨 열 마리 / 준호 협약)
3. **캐스트**: 만날 사람이 몇 명이고 누구인지 **이름과 역할**로 듣는다
4. **첫 접촉**: 최소 **4명**과 "이렇게 만났다"를 본다 (지금은 2명)
5. **첫 실패**: 흑역사 1개 = 실패가 기록된다는 규칙을 배운다
6. **형식 파괴**: 사진/알림 모먼트 1개 이상
7. **첫 관계 변화 카드**: "가까워졌다"를 한 번은 본다

### 7.4 데이터만으로는 불가능하다 (왜 엔진이 필요한가)

데이터만으로 §7.2 를 만들려면 두 가지가 막힌다.

1. **루트 칸은 지정할 수 없다.** `_pickRoute` 는 (오프닝은 균등, 4일차부터 호감 1위로) **캐릭터를 먼저 고르고**
   그 캐릭터의 후보 안에서 가중치 추첨한다. 특정 캐릭터의 r00 을 특정 날짜에 **보장**할 수단이 없다.
   (`e.day` 를 route 이벤트에 붙이면 그날만 후보가 되지만, **뽑힌다는 보장은 없다.**)
2. **일상 칸도 지정할 수 없다.** 가중치 추첨이고, `d_open_*` 10개가 `day [1,3]` 창에서 7칸을 나눠 갖는다.
3. **메인으로 옮기는 우회로도 막혀 있다.** `validate` 가 **같은 날 main 은 쪽별로 각 1개**만 허용한다
   (`main 날짜 중복`). 하루에 4칸을 메인으로 채울 수 없다. 게다가 `test/opening_test.dart` 는
   r00 이 **route 레이어**이고 `day.min == 1` 임을 고정한다(ROUTE_ORDER.md 가 "수정 금지 파일"로 부른다).

**⇒ 최소 엔진 변경 1개로 해결된다.** `GameConfig.openingScript: Map<int, List<String>>` 를 두고,

```dart
List<StoryEvent> planDay(GameState s) {
  final script = bundle.config.openingScript[s.day];
  if (script != null) {
    final plan = [for (final id in script) byId(id)!].where((e) => _available(s, e)).toList();
    if (plan.length >= script.length - 1) return plan;   // 한 칸 이상 비면 기존 로직으로 보충
  }
  ... // 지금 로직 그대로
}
```

약 20~30줄. `_available` 을 거치므로 선호·`once`·트리거가 그대로 지켜지고, 8일차부터는 지금 로직이 그대로 돈다.
`opening_test` 의 1~3일차 단정(`plan.first.id == 'm0N'`, 루트 1개 이상, 일상 2개 이상, 계획 4개 이상)은
§7.2 배치가 **그대로 만족**하므로 테스트를 고칠 필요도 거의 없다(4일차 `plan4.length ≤ 3` 만 4로 늘린다).

## 8. 판정 — 지금 구조로 이야기를 실을 수 있나

**실을 수 없다. 오프닝은 각본으로 고정해야 한다.** 이유 셋.

1. **배합비가 이야기를 허용하지 않는다.** 플롯은 읽는 것의 14.5%, 100일 중 58일은 0개, 3일에 하나.
   그 14.5%의 31%는 대사가 없는 지문이고, 후반 척추 8개는 상대의 이름을 부르지 않는다
   (부를 **수단이 엔진에 없다**). 나머지 58%는 3분의 1이 문맥 0, 3분의 2가 재방송,
   4분의 1은 이름 없는 사람에게 호감을 준다. 이 비율에서 관통선을 느끼는 것은 불가능하다.
2. **소개가 우연에 맡겨져 있다.** 캐스트 소개 화면은 첫 회차에서 도달 불가, 전제 문장은 80% 확률,
   "이렇게 만났다"는 4명 중 2명, 서연의 정체는 14일차, 준호는 11일차에 설명 없이 등장.
   루트 순서 감사(`ROUTE_ORDER.md`)는 **루트끼리의** 순서를 훌륭하게 잠갔지만,
   **"첫 접촉이 첫 등장보다 먼저"는 설계상 보장 대상이 아니었다** — 문서가 그 사실을 스스로 적어 두었다.
3. **액자가 시간만 말한다.** `D+N`·`N장`·요일·날씨는 매일 말하고, **"무슨 일이 있었나"** 는 어제 한 줄뿐인데
   그 한 줄조차 플롯 것이 아닐 확률이 절반이다. 장 제목은 비어 있고, 다시 읽을 화면도, 앱 밖 알림도 없다.

다만 **부품은 이미 다 있다.** `signals.json`(사건을 아는 12×7 관찰문), `TomorrowPeek`(이름을 부르는 예고),
`ContinueCard`(1위 + 신호), 캐스트 소개 화면, `chapterTitleFor`, 모먼트 형식, 인트로의 첫 문자 —
**전부 만들어져 있고 연결만 안 되어 있다.** 그래서 이 진단의 처방은 새 시스템이 아니라
**엔진 3곳(각본 훅 30줄, `{top}` 자리표시자, 클리프행어 우선순위 1줄) + UI 1곳(캐스트 소개 복원) +
새 글 2편**이다. 출시 전에 들어갈 수 있는 크기다.

이것을 하지 않고 출시하면, 리뷰는 "텍스트가 많은데 무슨 얘긴지 모르겠다"로 모인다 —
개발자가 자기 게임을 하면서 이미 그렇게 말했다.
