# 캐릭터 초상화 프롬프트 (ChatGPT 이미지 생성용)

모쏠 키우기 12명의 프로필 이미지를 ChatGPT 이미지 생성으로 만들 때 그대로 복사해 쓰는 문서다.
그림을 `assets/portraits/<id>.png` 로 넣으면 앱이 알아서 이니셜 원 대신 그림을 보여 준다(코드 수정 없음, §9).

- 근거: `docs/CAST_BIBLE.md`(12명 성격·아크·매력 포인트·외형 인상), `assets/story/characters.json`(역할·tagline·`mines`),
  `events_route_a.json`·`events_route_b.json`(대사에서 드러나는 분위기), `lib/ui/design_system.dart`의
  `characterAccents`(배경색).
- 등급 12+. 모두 **분명한 성인(20대 중반~후반)** 으로 그린다.
- 화풍만 바꾸면 실사로 교체할 수 있게 **공통 스타일 블록**과 **캐릭터 블록**을 나눴다. 캐릭터 블록에는
  화풍 단어를 넣지 않았다.

> **2026-09-20 개정 — 왜 바뀌었나**
> 이전 판으로 12명을 뽑았더니 "옷과 배경만 다르고 다 같은 사람"이라는 결과가 나왔다. 원인은 셋이었다.
> ① 캐릭터 블록에 **얼굴을 묘사한 항목이 아예 없었다**(머리와 옷만 달랐다).
> ② 일관성 가이드가 **같은 대화에서 이어 만들기**를 권했다 — 화풍뿐 아니라 얼굴까지 복사된다.
> ③ **구도·자세·시선·표정이 12명 전원 동일**하게 스타일 블록에 박혀 있었다.
> 이번 판은 얼굴 항목(얼굴형·눈·눈썹·코·입·피부·화장·특징)을 캐릭터마다 다른 값으로 지정하고,
> 구도·자세·시선·표정을 캐릭터 블록으로 내렸으며, **캐릭터마다 새 대화**를 기본 방식으로 바꿨다.

## 1. 쓰는 법 (요약)

1. ChatGPT에서 **캐릭터마다 새 대화를 연다.** (같은 대화에서 이어 만들면 얼굴이 복사된다. §5)
2. 한 대화에 **§2 공통 스타일 블록 + §4 해당 캐릭터 블록**을 한 번에 붙여 넣는다.
   화풍은 스타일 블록 문장이 고정하므로, 대화가 달라도 그림체는 유지된다.
3. 받은 이미지를 §8 체크리스트로 확인한다. 얼굴이 앞사람과 비슷하면 §6의 한 줄 지시문으로 고친다.
4. 12장이 모이면 **나란히 놓고 얼굴만 보고 구분되는지** 확인한다(§8 아래쪽). 구분이 안 되는 사람만 다시 뽑는다.
5. §9 규격대로 줄여 `assets/portraits/` 에 넣고, 앱을 **완전히 다시 빌드**해서(핫 리로드 X)
   디버그 갤러리의 "초상화 12명 미리보기"로 확인한다(§10).

권장 순서: 얼굴이 가장 대비되는 세 명(**다은 → 유나 → 승현**)을 먼저 뽑아 얼굴 폭을 벌려 놓고,
나머지 아홉 명을 만든다. 처음부터 비슷한 얼굴 두 명을 연달아 뽑으면 기준이 좁아진다.

## 2. 공통 스타일 블록 (모든 프롬프트 맨 앞에 붙인다)

화풍·채색·조명·배경·해상도·금지 항목만 들어 있다. **구도·자세·시선·표정은 캐릭터 블록(§4)에 있다.**

```
[스타일 — 일러스트]
한국 웹툰·모바일 연애 게임 프로필 스타일의 깔끔한 반실사 디지털 일러스트로 그려 주세요.
선: 가늘고 깨끗한 외곽선, 선 굵기 일정, 거친 스케치 선 없음.
채색: 부드러운 셀 채색에 가벼운 그라데이션, 피부는 맑고 자연스럽게(과한 광택·과한 보정 없음), 채도는 중간.
조명: 왼쪽 위에서 들어오는 따뜻하고 부드러운 자연광, 얼굴에 은은한 림라이트, 강한 그림자 없음.
얼굴 개성(가장 중요): 아래 [인물]에 적힌 얼굴형·눈·눈썹·코·입·피부·화장을 한 항목도 빼지 말고
그대로 반영해 주세요. 예쁘게 보이도록 이목구비를 평균적인 미형으로 바꾸지 마세요.
이 인물은 다른 어떤 인물과도 닮지 않은 고유한 얼굴이어야 하며, 자주 쓰는 기본 얼굴을 재사용하지 마세요.
프레임 안전 규칙: 1:1 정사각형 1024×1024. 얼굴은 가로 가운데, 머리 꼭대기부터 턱 끝까지가
세로 길이의 38~48%가 되게 하고 눈높이는 위에서 1/3 부근에 둡니다.
정사각형에 내접하는 원으로 잘라도 머리카락·얼굴·귀가 잘리지 않게 머리 위와 양옆에 여백을 남깁니다.
배경: 아래에 적은 색의 단색 평면 배경. 무늬·소품·풍경·그림자·질감·그라데이션 없음, 가장자리까지 같은 색.
인물은 한 명. 분명한 성인. 건전하고 단정한 차림.
넣지 말 것: 글자, 숫자, 말풍선, 로고, 브랜드 표시, 워터마크, 서명, 테두리 프레임, 다른 사람, 동물.
```

### 2.1 실사로 바꾸려면 — 위 블록 대신 이 블록을 붙인다

캐릭터 블록(§4)은 그대로 둔다. 프레임·배경·금지 항목이 같으므로 앱 쪽 원형 크롭도 그대로 맞는다.

```
[스타일 — 실사]
자연스러운 실사 인물 프로필 사진처럼 만들어 주세요. 85mm 렌즈, 조리개 f/2.8 느낌의 얕은 심도,
스튜디오의 부드러운 창가 조명(왼쪽 위에서 따뜻하게), 과한 보정·과한 피부 보정 없이 자연스러운 피부 결.
얼굴 개성(가장 중요): 아래 [인물]에 적힌 얼굴형·눈·눈썹·코·입·피부·화장을 한 항목도 빼지 말고
그대로 반영해 주세요. 모델처럼 보이도록 이목구비를 평균적인 미형으로 바꾸지 마세요.
이 인물은 다른 어떤 인물과도 닮지 않은 고유한 얼굴이어야 하며, 자주 쓰는 기본 얼굴을 재사용하지 마세요.
실존 인물이나 유명인을 닮지 않은, 가상의 평범한 한국인 얼굴.
프레임 안전 규칙: 1:1 정사각형 1024×1024. 얼굴은 가로 가운데, 머리 꼭대기부터 턱 끝까지가
세로 길이의 38~48%가 되게 하고 눈높이는 위에서 1/3 부근에 둡니다.
정사각형에 내접하는 원으로 잘라도 머리카락·얼굴·귀가 잘리지 않게 머리 위와 양옆에 여백을 남깁니다.
배경: 아래에 적은 색의 단색 무지 배경지(스튜디오 배경), 무늬·소품·그림자 없음.
인물은 한 명. 분명한 성인. 건전하고 단정한 차림.
넣지 말 것: 글자, 숫자, 로고, 브랜드 표시, 워터마크, 서명, 테두리 프레임, 다른 사람, 동물.
```

> 실사는 실존 인물 닮음 위험이 일러스트보다 훨씬 크다. §8의 역이미지 검색을 반드시 한다.
> 실사로 바꿀 때는 12장을 **한꺼번에** 바꾼다. 일러스트와 실사가 섞이면 한 게임처럼 보이지 않는다.

## 5. 12장을 한 게임처럼 맞추는 법 (일관성 가이드)

**기본 방식: 캐릭터마다 새 대화.** 화풍은 §2 스타일 블록의 문장이 고정한다. 같은 문장을 붙이면
대화가 달라도 그림체·채색·조명·배경 처리는 같게 나온다. 반대로 **같은 대화에서 이어 만들면
모델이 앞 이미지의 얼굴까지 복사해** 12명이 한 사람이 된다. 이게 지난번 실패의 가장 큰 원인이다.

1. **한 대화 = 한 캐릭터.** 새 대화를 열고 §2 스타일 블록 + §4 캐릭터 블록을 한 번에 붙인다.
   앞 캐릭터를 언급하지 않고, "방금 이미지와 같은 화풍으로" 같은 문장도 넣지 않는다.
2. **얼굴이 앞사람과 비슷하게 나오면** 같은 대화 안에서 한 줄만 덧붙여 다시 뽑는다.
   - `앞서 만든 인물과 완전히 다른 얼굴로 다시 그려 주세요. 얼굴형·눈매·코·입을 모두 바꿔 주세요.`
   - `쌍꺼풀 없는 홑꺼풀로 다시 그려 주세요.` / `속쌍꺼풀로, 선이 겉으로 보이지 않게 해 주세요.`
   - `눈을 더 작고 가늘게, 눈꼬리를 아래로 내려 주세요.`
   - `이목구비를 예쁘게 다듬지 말고 위 설명 그대로 그려 주세요.`
   §3 표에서 그 캐릭터의 값을 그대로 읽어 한 줄로 만들면 된다.
3. **화풍이 벌어진 것 같으면** 마음에 든 한 장을 **화풍 기준으로만** 참조시킨다.
   새 대화에 그 이미지를 첨부하고 맨 앞에 이 한 줄을 붙인다.
   ```
   첨부한 이미지의 화풍·선 굵기·채색·조명·배경 처리·얼굴 크기 비율만 그대로 따라 주세요.
   첨부 이미지의 인물 얼굴·머리·표정·자세는 절대 따라 하지 말고, 아래 설명의 인물로 완전히 다르게 그려 주세요.
   ```
   그다음 §2 스타일 블록 + 캐릭터 블록을 붙인다. **"얼굴은 다르게"를 빼면 참조 이미지의 얼굴이 그대로 복사된다.**
4. **다시 뽑을 때 바꾸면 안 되는 것**
   - §2 스타일 블록 전체(한 글자도 고치지 않는다. 고치면 12장을 다시 맞춰야 한다).
   - 1:1 비율, 단색 배경과 그 색 코드, 프레임 안전 규칙(머리 높이 38~48%).
   - 캐릭터 블록의 **얼굴 항목**(얼굴형·눈·눈썹·코·입·피부·특징)과 머리·옷·배경색.
     이게 §3 표에서 12명을 가른 값이라, 하나를 바꾸면 표에서 다른 사람과 겹치는지 다시 세어야 한다.
   - 자세·표정 문장은 다듬어도 된다(단, 자세는 12명이 서로 달라야 하므로 다른 사람 자세로 바꾸지 않는다).
5. **부분만 고칠 때**는 ChatGPT의 이미지 편집(영역 선택)으로 "이 부분만 ○○로" 고친다.
   전체를 다시 뽑으면 얼굴이 통째로 바뀐다. 손·소품 오류는 부분 편집이 가장 빠르다.
6. **손은 최소로.** 손이 크게 나오면 AI 오류(손가락 개수·관절)가 잦다. 손이 프레임에 들어오는 사람은
   지우(팔짱)·예은(두 손)·건우(턱 괴기)·소희(헤드셋에 얹은 손) 넷뿐이다. 손이 이상하면
   `손이 화면 아래로 나가도록 조금 더 위에서 잘라 주세요.` 를 붙인다.
7. **색 확인.** 배경이 캐릭터 색 코드와 크게 다르면 `배경을 #XXXXXX 단색으로만 바꿔 주세요.` 로 편집한다.
   앱에서 원 바깥(강조색 container)과 그림 배경이 이어져 보이는 게 목표다.

## 6. "다 비슷해 보일 때" 문제 해결

증상 → 원인 → 붙여 넣을 한 줄. 전체를 다시 뽑기 전에 여기부터 본다.

| 증상 | 원인 | 고치는 한 줄 |
|---|---|---|
| **얼굴이 다 같은 사람이다** | 같은 대화에서 이어 만들었거나, 참조 이미지에 "얼굴은 다르게"를 안 붙였다 | 새 대화를 열고 §2 + 캐릭터 블록만 붙인다. 그래도 같으면 → `앞서 만든 인물과 완전히 다른 얼굴로, 얼굴형·눈매·코·입을 모두 바꿔 그려 주세요.` |
| **눈이 12명 다 똑같이 크고 또렷하다** | 모델이 기본 미형 얼굴로 되돌아갔다 | `쌍꺼풀 없는 홑꺼풀로, 눈을 더 작고 가늘게, 눈꼬리를 아래로 내려 그려 주세요.` (§3 표의 그 사람 값을 넣는다) |
| **머리 색만 다르고 얼굴은 같다** | 프롬프트에서 얼굴 항목이 무시됐다 | `머리 스타일은 그대로 두고, 얼굴형과 이목구비만 아래 설명대로 완전히 다시 그려 주세요.` + 얼굴 항목 4줄만 다시 붙인다 |
| **자세가 12명 다 똑같다** | 스타일 블록에 구도를 다시 써 넣었다 | 스타일 블록에서 구도·자세·시선 문장을 지운다. 그다음 → `자세를 바꿔 주세요: (§3 표의 그 사람 자세 한 줄).` |
| **나이가 어려 보인다 / 학생 같다** | 눈이 크고 볼살이 많으며 화장이 없다 | `20대 후반의 성숙한 성인 얼굴로, 얼굴 비율을 세로로 길게 하고 볼살을 줄여 주세요. 눈은 지금보다 작게.` |
| **나이가 너무 들어 보인다** | 음영·주름이 과하다 | `20대 중반으로, 눈가·팔자 주름과 얼굴 음영을 줄여 주세요. 피부는 매끄럽게.` |
| **배경에 무늬·그림자·질감이 생긴다** | 단색 지시가 약하다 | `배경을 #XXXXXX 하나의 평면 단색으로만 채워 주세요. 그라데이션·질감·그림자·소품 없이 가장자리까지 같은 색.` |
| **원으로 자르면 머리 꼭대기가 잘린다** | 얼굴이 너무 크게 잡혔다 | `조금 더 멀리서 잡아, 머리 꼭대기 위와 양옆에 여백을 더 남겨 주세요. 얼굴 크기는 세로 길이의 40% 정도로.` |
| **얼굴 크기가 12장마다 제각각이다** | 상반신 범위 차이가 과장됐다 | `머리 꼭대기부터 턱 끝까지가 세로 길이의 40%가 되게 맞춰 주세요.` (12장 모두 같은 숫자로) |
| **화풍이 앞 장들과 다르다** | 스타일 블록을 고쳤거나 일부만 붙였다 | §2 스타일 블록을 원문 그대로 다시 붙이고, 그래도 다르면 §5-3의 화풍 참조 방식을 쓴다 |
| **옷·소품에 글자나 로고가 생긴다** | 금지 목록이 뒤로 밀렸다 | `옷·앞치마·소품에 있는 글자, 숫자, 로고, 무늬를 모두 지우고 무지로 바꿔 주세요.` |
| **특징(점·주근깨·보조개)이 안 보인다** | 작은 디테일이 뭉갰다 | `(왼쪽 눈 밑의 작은 점)을 또렷하게 보이도록 그려 주세요.` — 한 번에 하나만 요청한다 |
| **여성 캐릭터가 다 같은 화장이다** | 화장 항목을 빼먹었다 | `입술은 (버건디 매트 / 붉은 틴트 그라데이션 / 누드 베이지 / 핑크 글로스 / 무색 립밤) 로, 눈 화장은 (없음 / 검정 아이라인 / 펄 섀도) 로 해 주세요.` |
| **남성 캐릭터가 다 같은 얼굴이다** | 남성은 피부결·수염·눈썹 정리로 갈린다는 걸 빠뜨렸다 | `수염은 (없음 / 하루 지난 자국 / 듬성듬성 짧게 / 짧게 정돈한 턱수염 라인) 로, 눈썹은 (손대지 않음 / 끝만 정리 / 깔끔히 정리) 로 해 주세요.` |
| **안경·헤드셋·청진기가 망가진다** | 구조물은 AI 오류가 잦다 | 부분 편집으로 그 영역만 고친다. 안 되면 `안경테가 얼굴 뒤로 끊기지 않고 귀까지 이어지게 다시 그려 주세요.` |

## 7. 원형 크롭 규칙 (앱에서 어떻게 잘리는지)

- 앱은 정사각형 이미지를 **내접원**으로 자른다(가장자리 네 귀퉁이가 사라짐). 가장 큰 곳은 전화 화면 96pt,
  캐스트 소개 카드 72pt, 가장 작은 곳은 32pt(이어하기 카드·단톡 줄).
- 그래서 머리 꼭대기와 양쪽 귀가 원 안에 들어와야 하고, 소품은 원의 아래쪽 가운데에 있어야 보인다.
- 32pt에서는 얼굴 디테일이 사라지므로 **헤어 실루엣과 머리색**이 누구인지를 가른다(§3.2가 이걸 가른 이유).
  72pt 이상에서는 얼굴형·눈매·화장이 보이기 시작한다(§3.1이 이걸 가른 이유). 두 층 모두 필요하다.
- 가장자리에 강조색 1pt(전화 화면은 2pt) 테두리가 그림 위에 얹힌다. 배경을 강조색 계열로 두면 테두리가 자연스럽다.

## 8. 체크리스트 (한 장마다, 그리고 12장 모아서)

한 장마다:
- [ ] **얼굴 항목 대조**: §3.1 표의 그 사람 줄과 그림을 나란히 본다. 얼굴형·쌍꺼풀 유무·눈꼬리 방향·
      눈썹 모양·특징(점/주근깨/보조개/흉터)이 표대로인가. 하나라도 다르면 §6의 한 줄로 고친다.
- [ ] **상업적 이용 약관**: 이미지를 만들 때 쓴 ChatGPT 요금제·시점의 이용 약관에서 생성물의 소유권과
      상업적 이용(앱 내 사용, 스토어 스크린샷)이 허용되는지 확인하고, 확인한 날짜와 약관 링크를 기록해 둔다.
- [ ] **실존 인물 닮음 없음**: 역이미지 검색(Google 렌즈, 네이버 스마트렌즈 등)으로 비슷한 실존 인물·연예인
      사진이 나오지 않는지 확인. 닮았다고 느껴지면 얼굴형·눈매 문장을 바꿔 다시 뽑는다.
- [ ] **분명한 성인으로 보이는가**: 얼굴 비율·옷차림이 20대 중후반으로 보이는지. 앳되어 보이면 §6의
      "나이가 어려 보인다" 줄을 쓴다.
- [ ] **선정성 없음**: 노출·몸매 강조 없음, 트레이너는 지퍼 올린 상의.
- [ ] **AI 오류**: 손가락 개수·관절, 눈동자 좌우 크기·방향, 귀걸이 짝, 안경테 끊김(정우), 헤드셋(소희)·
      청진기(승현) 구조, 이너 컬러 위치(소희), 땋은 머리·포니테일이 끊기지 않는지, 캡 챙과 머리카락 경계(민재).
- [ ] **글자·로고 없음**: 옷, 앞치마, 편지 봉투, 가운에 알아볼 수 있는 글자나 로고가 없는지(흐릿한 가짜 글자도 지운다).
- [ ] **원형 크롭 미리보기**: 원으로 잘랐을 때 머리 꼭대기·귀가 잘리지 않는지. 디버그 갤러리의
      "초상화 12명 미리보기"에 원형 가이드 선이 있다(§10). 넣기 전에는 macOS 미리보기에서 정사각형 가운데 원을 눈으로 확인.
- [ ] **배경**: 단색이고 색 코드와 가까운지, 무늬·그림자가 없는지.

12장 모아서:
- [ ] **12장을 나란히 놓고, 머리와 옷을 가린 채 얼굴만 보고도 12명이 구분되는가.**
      (손이나 종이로 머리·옷을 가리고 본다. 구분이 안 되는 사람이 있으면 그 사람만 §3.1 값으로 다시 뽑는다.
      이 항목이 이번 개정의 핵심이다.)
- [ ] 12장을 한 화면에 나란히 놓고(디버그 갤러리 맨 위 줄) 화풍·선 굵기·채도·밝기·얼굴 크기가 같은지.
- [ ] 같은 쪽 6명끼리 32pt 크기에서도 누가 누구인지 헤어 실루엣만으로 구별되는지.
- [ ] 자세가 12명 서로 다른지(§3.2 자세 열과 대조). 세 명 이상이 같은 자세면 다시 뽑는다.
- [ ] 라이트·다크 모드 둘 다에서 테두리와 그림이 어색하지 않은지(갤러리 상단 세그먼트로 전환).
- [ ] 히든 두 명(유나·도윤)은 공개 전 화면에서 실루엣으로 가려지는지(앱이 처리한다. 확인만).

## 9. 파일 규격과 넣는 법

| 항목 | 규격 |
|---|---|
| 경로 | `assets/portraits/<id>.png` (예: `assets/portraits/seoyeon.png`) |
| 파일 이름 | 캐릭터 id 그대로, **영문 소문자**. `seoyeon` `haneul` `jiwoo` `minjae` `yeeun` `doyun` `jeongwoo` `daeun` `seunghyun` `sohee` `geonwoo` `yuna` |
| 형식 | PNG 권장. JPG(`.jpg`/`.jpeg`)도 된다. 같은 id에 둘 다 있으면 PNG를 쓴다 |
| 크기 | 정사각형. 원본은 1024×1024로 보관하고, 앱에 넣는 파일은 768×768 권장(가장 큰 표시 96pt × 3배 = 288px의 2.5배 이상) |
| 용량 | 한 장 **200KB 이하** 권장(12장 합계 2.4MB 이하) |
| 하위 폴더 | 쓰지 않는다. `assets/portraits/draft/…` 는 무시된다 |

ChatGPT가 주는 PNG는 한 장에 1~2MB라 줄여서 넣는다. 원본은 저장소 밖(예: `~/Pictures/mossol_portraits/`)에 보관한다.
macOS 기본 명령 `sips` 만으로 된다.

```sh
# 원본 폴더에서 앱용 JPG 로 줄이기 (768px, 품질 80 → 보통 70~150KB)
cd ~/Pictures/mossol_portraits
for id in seoyeon haneul jiwoo minjae yeeun doyun jeongwoo daeun seunghyun sohee geonwoo yuna; do
  [ -f "$id.png" ] || continue
  sips -z 768 768 -s format jpeg -s formatOptions 80 "$id.png" \
    --out ~/workspace/mossol/assets/portraits/$id.jpg
done
ls -lh ~/workspace/mossol/assets/portraits

# PNG 로 넣고 싶으면 크기만 줄인다(용량은 JPG 보다 크다. 200KB 를 넘으면 JPG 로)
sips -z 768 768 seoyeon.png --out ~/workspace/mossol/assets/portraits/seoyeon.png

# 크기 확인
sips -g pixelWidth -g pixelHeight ~/workspace/mossol/assets/portraits/*.jpg
```

파일을 넣은 뒤 할 일:
- **코드·JSON 수정 없음.** `pubspec.yaml` 에 `assets/portraits/` 폴더가 이미 등록돼 있고, 앱이 시작할 때
  `AssetManifest` 를 읽어 `<id>.png|jpg` 가 있는 캐릭터만 그림으로 바꾼다. 없는 캐릭터는 이니셜 원 그대로다.
  몇 장만 먼저 넣어도 된다.
- 새 파일은 번들에 들어가야 하므로 **앱을 완전히 다시 실행**한다(핫 리로드·핫 리스타트로는 안 보일 수 있다).
  `flutter run` 을 끄고 다시 켜거나, 시뮬레이터용은 `flutter build ios --simulator --debug` 후 실행.
- `assets/portraits/.gitkeep` 은 지우지 않는다(빈 폴더여도 빌드가 깨지지 않게 하는 파일).

## 10. 넣은 뒤 앱에서 확인하는 순서

1. `flutter run --dart-define=MOSSOL_DEBUG_GALLERY=true` → 디버그 갤러리 → **초상화 → 초상화 12명 미리보기**.
   - 맨 위 "12명 중 N장 있음"으로 인식 여부 확인(0장이면 파일 이름·경로·재빌드를 확인).
   - 맨 위 줄: 12명 나란히(화풍 통일 + 얼굴 구분).
   - 캐릭터마다: 원본 정사각형 + 원형 가이드 선, 실제 크기 32·40·56·72·96, 히든은 미공개 실루엣.
   - 상단 세그먼트로 라이트·다크 전환.
2. 같은 갤러리에서 **새 게임 온보딩 → 2단계: 캐스트 소개**(여성·남성): 카드 아바타 72pt(320pt 폭 폰은 56pt).
   이 크기에서 얼굴이 구분되는지가 실제 사용자 경험에 가장 가깝다.
3. **모먼트 미리보기 → 전화**: 수신 화면의 큰 원(96pt)과 통화 중 작은 원(40pt).
4. **정산·홈 미리보기**: 관계 변화 카드(40pt), 이어하기 카드(32pt), 홈 사람들 줄(40pt).
5. 실제 게임을 시작해 채팅 화면까지 한 번 본다(아래 "알려진 한계" 참고).
6. `flutter test test/widget/portrait_test.dart test/widget/layout_test.dart` 로 넘침이 없는지 확인.

알려진 한계: 채팅 화면 헤더의 작은 원(`event_screen.dart` 의 `_AvatarDot`)은 아직 이니셜이다. 그 파일은 다른 작업이
진행 중이라 이번 작업에서 건드리지 않았다. `CharacterAvatar(name:, characterId: ev.character, accent:, size: 32)` 로
바꾸면 같은 규칙으로 그림이 뜬다.
