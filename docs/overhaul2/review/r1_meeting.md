# 1라운드 개선 회의록 (2026-10-07)

참석(보고서): Game Designer(`r1_game_design.md`) · Narrative Designer(`r1_script.md`) · Code Reviewer(`r1_bugs.md`) · Reality Checker(`r1_playtest.md`, `r1_shots/`)
진행: 메인 세션. 종료 기준: 다음 라운드 검토에서 **새 P0·P1 0개**.

## 1. 결론

- 새 시작 스토리의 첫 10분 훅은 확실히 좋아졌다. 평균 점수 6~8로 클래식은 3이다.
- 5회 이상 다시 할 이유가 부족하다. 2회차 이후가 지루하고, 고른 갈래가 증발하며, 진상 선택은 평판 세금처럼 느껴진다.
- 대본 P0 29건의 대부분은 네 가지 패턴이다.
  - 인트로가 D1을 미리 말해 버림
  - 클리프행어가 보이지 않음
  - r00 첫 만남과 모순
  - 돈 단위가 10배 차이남
- 버그는 P0이 0건이다. P1은 3건이다: 정산 게이지 넘침, 인트로·홈의 운명 뽑기 재추첨, 가속 캐릭터가 D1~3에 나오지 않음.
- 시뮬레이터 런타임이 없어 실기기 화면 확인은 다음 라운드로 넘긴다. 사용자에게 런타임 설치를 요청한다.

## 3. 데이터 계약 (두 담당이 함께 지킨다)

- `villain`: 숨김 스탯, 0~99, 기본 0. 진상 선택의 `effects.stats.villain: 1`. 트리거는 `"stats":{"villain":[3,99]}` 형식.
- `clock`: 이벤트 최상위 필드. `"01:12"` 처럼 쓴다. 없으면 기존처럼 하루 안 위치로 시각을 정한다.
- `done_<startId>` (`done_classic`, `done_sc_leak` …)와 `veteran`(엔딩을 본 시작이 1개 이상): 엔진이 새 게임 때 세운다. 대본은 `trigger.flags` 로 읽기만 한다. 검증기의 "읽는 플래그는 어딘가에서 세워져야 한다" 규칙에 엔진 플래그로 등록한다.
- `starts.json` 의 `recommended: true` 필드(선택). 엔진이 읽어 "처음이라면" 배지를 붙인다.
- `starts.json` 텍스트와 `endings.json` 은 대본 담당, `config.json` 은 엔진 담당이 고친다.
