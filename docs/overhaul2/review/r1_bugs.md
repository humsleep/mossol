- 엔진 경로(D1~10, 결정적 선택). 시작 6종 × 선호 f/m × D1 분기 0~3 × 미니게임 성공/실패, 모두 96판을 돌렸다.
  예외 0건. 대사 0줄·선택지 0개 이벤트 0건. 선택지가 전부 잠긴 이벤트 0건. 하루에 같은 이벤트 두 번 0건.
  빈 큐인 날 0일. `next` 대상 누락 0건. 치킨 내기(`d_open_bet`)는 모든 판에서 정확히 1번 나왔다.
- 100일 무작위. 시작마다 시드 50개, 모두 300판을 돌렸다. 모든 판이 엔딩에 닿았다. 소문 값은 0~100 을 벗어나지 않았다.
  이번 변경에서 나온 불변식 위반은 0건이다(같은 날 두 번 나온 것은 아래 "범위 밖" 1건뿐이다).
- 하루 도중 저장·복원. 시작 6종 × f/m × 시드 6개로, 선택 전과 선택 후에 앱을 끄고 `continueGame` 으로 다시 켰다.
  플래그, 소문, 거른 화면(대사·선택지·반응 줄 문구), 남은 큐가 모두 같았다.
- 예전 세이브. D50 세이브(선호 없음, f, m 각각, `heat` 키 없음)와 D2 세이브(m01·내기를 이미 봄)를 시드 20개씩 100일까지 이어 했다.
  `events_start.json` 이벤트 노출 0건, `sc_*`/`start_alt` 조건 줄 노출 0건, 내기 재등장 0건, 모든 판이 엔딩에 닿았다.
  소문을 올린 것은 클래식에도 열린 의뢰 4종(`a_hustle_reply/guest/mc/review`)뿐이었다. 의도한 동작이다.
- 템플릿. 새 이벤트 75개, 의뢰, 기존 이벤트에 더한 파급 줄·선택지를 f/m × 이름 4종(민석/민지/Jin/없음)으로 치환했다.
  남은 `{…}` 0건, 빈 줄·이중 공백 0건, `{char:…}` 가 "그 사람"으로 떨어진 경우 0건이었다. 이름 토큰 바로 뒤에
  조사를 직접 붙인 곳(`{char:a,b}은` 형태)도 0건이다. 조사는 모두 `|은는` 등 템플릿 문법으로 처리돼 있다.
  예: 다은(받침 있음)/하늘(ㄹ 받침)의 `으로로`도 `finalOf` 가 맞게 고른다.
- 시작 카드 시트. 320×568 화면, 글자 배율 1.0·1.6·2.0 에서 카드 6장과 운명 카드를 끝까지 스크롤해도 넘침이 없었다.
  잠긴 카드를 탭하면 시트가 닫히지 않고 훅이 펼쳐지며, 다시 탭하면 접힌다.
- 엔딩 화면의 "N회차 시작"을 두 번 탭해도 시트는 하나만 열린다.
- 광고·분석. 전면 광고는 정산 화면에서만 부르고(`summary_screen.dart:182`) 새 화면은 광고 경로를 건드리지 않는다.
  `runStart(start:)` 는 `newGame` 에서만 남는다(인트로·홈·엔딩 모두 `newGame` 을 한 번 부른다).
- 기존 테스트 전체(`flutter test`)는 내 임시 테스트를 빼면 모두 통과했다.

## P1

### R1-1. 정산 화면의 소문 게이지가 가로로 넘친다(RenderFlex overflow)

- **위치**: `lib/ui/heat_gauge.dart:80-140`(Row), 호출부 `lib/ui/summary_screen.dart:118-125`
- **원인**: Row 안에서 `Flexible` 은 구간 이름 하나뿐이다. 아이콘, "소문", 5칸, 변화량(`+25`), "밤사이 −1" 은 모두 고정 폭이다.
  정산에서는 `delta` 와 `overnight` 가 함께 붙어 고정 폭 합계가 카드 폭을 넘는다.
- **재현**: `r1_scripts/zz_r1_ui_test.dart.txt`
  - `HeatGauge at summary width …`: 폭 248(320 − 화면·카드 여백), heat 88, delta +15, overnight −1.
    배율 1.0 에서 15px, 1.3 에서 55px, 1.6 에서 95px, 2.0 에서 148px 넘친다.
  - `SummaryScreen real …`: 실제 정산 화면, sc_clip, heat 90, 오늘 +25.
    - 320×568: 배율 1.0 에서 15px, 1.3 에서 55px 넘친다.
    - 375×667: 1.0, 1.3 모두 정상이다.
    - 390×844: 배율 1.6 에서 25px 넘친다.
  - 홈 게이지(변화량·밤사이 없음)는 320폭, 배율 1.0·1.6 에서 정상이다.
- **영향**: iPhone SE 1세대 크기 또는 큰 글자를 쓰는 사용자의 정산 화면에 노란 줄무늬가 보이고 "밤사이 −1" 이 잘린다.
  소문 회차에서는 정산을 매일 보므로 노출이 잦다.
- **제안**:
  - Row 를 `Wrap` 으로 바꾼다. 또는 두 줄로 나눈다(1줄: 아이콘·이름·5칸·구간, 2줄: `+25 · 밤사이 −1`).
  - 최소한 변화량과 밤사이 문구를 `Flexible` + `TextOverflow.ellipsis` 로 감싼다.
  - 회귀 테스트는 위 스크립트의 `SummaryScreen real 320×568 ×1.3` 경우를 그대로 쓰면 된다.

### R1-2. 인트로에서 운명 뽑기를 다시 뽑을 수 있다(홈에서 고친 문제가 인트로에는 남아 있음)

- **위치**:
  - `lib/ui/intro_screen.dart:294` `StartPickSheet.showFor(context, c)`: `fateLocked` 를 넘기지 않는다.
  - `lib/ui/intro_screen.dart:414-423` `_backToStart`: `_startId = null` 로 지운다.
- **재현**: `r1_scripts/zz_r1_flow_test.dart.txt` 의 `intro: fate then "다른 일이었어" …`
  1. 첫 실행 인트로에서 "한다"를 누른다.
  2. 시트에서 운명 뽑기를 누른다.
  3. 이름 단계에서 "아니, 다른 일이었어"를 누른다.
  4. 다시 열린 시트의 `fateLocked == null` 이다(테스트 실패로 확인).
  5. 운명 카드 안내도 "다시 뽑을 수 없어요"가 아니라 처음 문구다. 다시 누르면 새로 뽑는다.
- **영향**:
  - 1회차 플레이어가 원하는 잠긴 시작(sc_swap, sc_ghost)이 나올 때까지 무한히 다시 뽑을 수 있다.
    §4.3 의 "이번 회차만 열림"이 해금 동기라는 설계가 무너진다.
  - 반대로, 운이 좋게 잠긴 시작이 나왔는데 뒤로 가면 그 카드는 다시 잠겨서 고를 수 없다.
  - 같은 구멍이 홈에도 있다. `lib/ui/home_screen.dart:352` 의 `String? fate` 는 `_startNewGame` 안의 지역 변수다.
    그래서 시트를 닫고 "새 게임"을 다시 누르면 다시 뽑을 수 있다. 뒤로 가기 경로는 막았지만 닫기 경로는 열려 있다.
- **제안**:
  - 인트로: `_IntroScreenState` 에 `String? _fate` 를 두고 `showPickFor(..., fateLocked: _fate)` 로 바꾼다.
    결과가 `fate` 면 `_fate` 에 기억한다. `_backToStart` 는 `_startId` 만 지우고 `_fate` 는 지우지 않는다.
  - 홈의 닫기 경로까지 막으려면, 뽑은 운명을 메타(예: `pendingFate`)에 두었다가 `newGame` 에서 지운다.
    추가만 하는 필드다. 또는 컨트롤러 메모리에 두고 앱을 다시 켤 때까지 유지한다.

### R1-3. "먼저 다가오는 사람" 가속이 D1~3 에 아무 효과가 없다(§3.0·§7.1 "망가짐" 기준 위반)

- **위치**: `lib/engine/event_engine.dart:559-560` `_pickRoute`. 오프닝(D1~3)에는 호감을 보지 않고 루트 후보 중 **균등 무작위**로 고른다.
  시작 보정 +4 는 D4 부터만 순위에 반영된다.
- **재현**: `r1_scripts/zz_r1_sim_test.dart.txt` 의 `accelerated role r00 within D1-3`(시작마다 f/m 시드 100개).

  | 시작 | 가속 대상 r00 이 D1~3 에 나온 비율 | D1~5 |
  |---|---|---|
  | sc_leak / sc_speech / sc_swap (f·m) | 53% | 99~100% |
  | sc_clip (f·m) | 53% | 93% |
  | sc_ghost (f·m) | **0%** | **0%** |

  - 53% 는 가속이 없을 때의 기댓값과 같다(후보 4명, 3일 → 1−(3/4)³ ≈ 58%).
  - sc_ghost 의 지우·승현은 r00 이 아예 없거나(`jiwoo`) D5 이후에 `seunghyun_intro` 를 요구한다.
    그래서 "먼저 다가오는 사람" 카드 문구와 실제 동작이 다르다.
- **근거**: 01_design §7.1 "가속 역할의 r00 이 D1~3 에 나오지 않으면 망가진 것이다". §3.3 "D2 에 그 사람이 먼저 개인톡을 보낸다".
- **제안**(택1):
  1. 엔진에서 처리한다. 오프닝 루트 추첨에서 `startAffectionOf(s, id) > 0` 인 캐릭터를 D1~3 중 하루(예: D2)에 우선한다.
     또는 가중치를 2~3배로 준다. 클래식은 보정이 없으므로 opening_test 의 균등 불변식이 그대로 남는다.
  2. 데이터에서 처리한다. 시작마다 D2 main 의 선택지 `next` 로 가속 대상의 r00(또는 r00 에 준하는 첫 접촉 장면)을 연다.
     sc_ghost 는 소개팅 짝의 첫 접촉 장면을 새로 만들거나, 카드의 "먼저 다가오는 사람" 표기를 고친다.
  - 어느 쪽이든 위 비율 표를 회귀 테스트로 고정한다(목표: D1~3 에서 100%).

## P2

### R1-4. main 날짜 검증 키가 갈래 플래그를 다른 "시작"으로 본다(잠재 구멍)

- **위치**: `lib/engine/story_repository.dart:497` `mainStartKey`. `trigger.flags` 에서 `sc_` 로 시작하는 **첫 플래그**를 시작 id 로 쓴다.
- **문제**: `sc_clip_deny` 같은 **갈래 플래그**도 `sc_` 로 시작한다. 그래서 `flags:[sc_clip]` main 과 `flags:[sc_clip_deny]` main 이
  같은 날 있어도 키가 달라 검증을 통과한다. 하지만 deny 갈래 회차에서는 둘 다 후보에 올라 하루에 main 이 둘이 된다.
  지금 데이터에는 해당 사례가 없다. 작가가 갈래별 main 을 넣는 순간 터진다.
- **재현**: `r1_scripts/zz_r1_validator_test.dart.txt`. 합성 번들에서 검증을 통과한 뒤
  `candidates(main)` 이 `[m_a, m_b]` 두 개를 돌려준다.
- **제안**: 키를 `bundle.startById` 에 실제로 있는 id 로만 인정한다. 또는 접두어 일치 시 "가장 긴 시작 id 의 접두어"로
  정규화한다(`sc_clip_deny` → `sc_clip`). 갈래 키는 같은 시작과 겹치는 것으로 본다.

### R1-5. 실행할 때마다 도는 검증이 약 19% 느려졌다

- **위치**: `StoryBundle.validate`. 새 검사(`_checkFlagGates`, `_checkFlagRefs`, `_checkStarts`)와 `_viewCases` 의 플래그 축(`flagSets`)이 추가됐다.
- **측정**: `r1_scripts/zz_r1_perf_test.dart.txt`. 데스크톱 JIT 에서 `fromJsonStrings` 를 6회 반복해 HEAD 워크트리와 비교했다.
  - 첫 회: 220ms → 305ms
  - 안정 후 최소: 77ms → 92ms
  - 이벤트 75개가 늘어난 몫이 포함돼 있다. 기기 AOT 에서는 절대값이 다르지만 비율은 비슷할 것이다.
- **판단**: 지금 수준은 허용 범위다. 다만 `_viewCases` 는 (MBTI 17 × 목소리 13 × 플래그 축 2+n) 곱으로 늘어난다.
  `d_brief_alt` 처럼 파급 줄이 많은 이벤트에 목소리 조건까지 붙으면 급격히 커진다.
- **제안**: 출시 빌드에서는 무거운 화면 검사(`_viewCases` 계열)를 `kDebugMode`/테스트에서만 돌린다.
  필수 검사(키·참조·날짜 중복)만 출시 실행에 남긴다. 테스트 쪽 `requireEndingHints` 처럼 플래그로 나누면 된다.

### R1-6. 온보딩 퍼널: 시작 카드 단계가 기록되지 않고, 되돌아가면 `name` 단계가 중복 기록된다

- **위치**: `lib/ui/intro_screen.dart:316`(`_openStart` 안의 `logOnboardingStep(stepName)`), `:414` `_backToStart`
- **문제**:
  - 시작 카드 시트에서 이탈한 사용자는 퍼널에서 "deal 다음 name 직전" 이탈로 보인다. 별도 `start` 단계가 없다.
  - "다른 일이었어"로 되돌아가 다시 고르면 `onboarding_step{step:name}` 이 두 번 남아 단계 전환율이 부풀려진다.
- **재현**: 코드 경로 확인. `r1_scripts/zz_r1_flow_test.dart.txt` 의 인트로 시나리오가 `_openStart` 를 두 번 지난다.
- **제안**: `Analytics.stepStart = 'start'` 를 추가해 시트가 처음 열릴 때 한 번 남긴다. `stepName` 은 이 흐름에서 한 번만
  남도록 플래그로 막는다. 운명 뽑기 여부(`fate: 1`)를 `run_started` 에 덧붙이면 §7.4-2 결정에 쓸 수 있다.

### R1-7. §4.3 카드 명세 중 빠진 것 2개

- **위치**: `lib/ui/start_pick_sheet.dart:254-259` `_badgeOf`
- **내용**:
  - 배지 "본 적 있음(엔딩 n개)"가 구현돼 있지 않다.
  - "2회차 이후 기본 선택은 아직 안 해 본 시작 중 첫 번째"도 없다. 강조나 스크롤 위치가 없어 매번 클래식이 맨 위에 보인다.
    "클래식으로 돌아가는 관성을 끊는다"는 의도가 빠졌다.
- **제안**: 시작별 플레이 기록이 필요하다. 메타에 `startsPlayed: {id: endings}` 를 추가만 하는 필드로 두고 `_finish` 에서 채운다.

- `mo_fail_drunk_replay` 가 같은 날 두 번 나온다(classic, 시드 19·32, D85).
