- 날짜: 2026-10-07 · 브랜치 `overhaul2-starts`(커밋 전 작업본) · 점검: RealityIntegration
- **판정: NEEDS WORK** (출시 차단급 P0 은 없음. P1 3건은 다음 빌드 전에 고쳐야 함)

## 0. 어떻게 봤나 (그리고 무엇이 "실기기"가 아닌가)

- **iOS 시뮬레이터로 돌리지 못했다.** `xcrun simctl list runtimes` 가 비어 있다. 하나 있는 기기(iPhone 17 Pro Max)는
  `iOS-26-5 runtime profile not found` 로 사용 불가였다. 런타임 설치(수 GB 다운로드)와 사용자의 실물 iPhone(무선 연결,
  TestFlight 앱 데이터 덮어쓸 위험)은 허락 없이 쓰지 않았다. 그래서 `integration_test` 도 돌릴 수 없었다.
- 대신 **위젯 테스트로 실제 앱 트리(`MossolApp`)를 처음부터 끝까지 탭으로 몰고**, 각 단계에서 `RepaintBoundary.toImage`
  로 PNG 를 구웠다. 실제 Pretendard 4종·MaterialIcons 폰트, 실제 `assets/story/*.json`, 실제 `SceneRegistry`·
  `PortraitRegistry`(AssetManifest) 를 올려서 그림·글자는 실기와 같은 자산으로 그려졌다.
  화면 393×852(아이폰 15 급), 375×667(SE), 320×568 + 글꼴 1.3배, 다크 모드로 찍었다.
- 실기와 다른 점: 노치·홈 인디케이터 safe area 가 0, 실제 애니메이션 프레임·햅틱·소리·광고·ATT 팝업 없음, 성능(로딩 시간) 측정 불가.
- 하네스는 `test/widget/zz_r1_shots_test.dart`(임시)로 만들었고, 끝난 뒤 지웠다. 11개 시나리오 모두 통과했고
  **어느 화면에서도 RenderFlex overflow 같은 Flutter 예외가 잡히지 않았다**(매 촬영 뒤 `takeException()` 확인).

### P1

**P1-1. 첫 실행 인트로에서 운명 뽑기를 무한히 다시 뽑을 수 있다 (잠긴 시작 맛보기 규칙이 깨짐)**
- 근거: `04_a5_fate_result.png` → `05_a6_sheet_after_fate_back.png`. 운명으로 `sc_ghost` 를 뽑은 뒤 "아니, 다른 일이었어"를 누르면
  시트가 운명 고정 없이 다시 열린다. sc_ghost 는 다시 잠겨 있고, 운명 카드 문구도 "이번 운명은 …. 다시 뽑을 수 없어요"가 아니라 처음 문구다.
- 원인: 홈 흐름(`home_screen.dart` `_startNewGame`)은 `showPickFor(fateLocked: fate)` 로 고정하지만, 인트로(`intro_screen.dart` `_openStart`)는
  `StartPickSheet.showFor(context, c)` 만 불러 `fateLocked` 를 넘기지 않는다. 시트 주석이 막겠다고 한 "뒤로 가서 다시 뽑기"가 인트로에서는 열려 있다.
- 재현: 새로 설치 → 타이틀 → 알림 → "한다" → 시트에서 운명 뽑기 → 이름 단계에서 "아니, 다른 일이었어" → 운명 뽑기 반복.
- 영향: 1회차부터 잠긴 두 시작을 원하는 만큼 골라 들어갈 수 있어 해금 동기가 사라진다. 측정(운명 여부)도 인트로 경로에서는 남지 않는다.

**P1-2. 새벽 장면인데 말풍선 시각은 "오전 9:43"**

- 원인: `event_screen.dart` 의 `startSeconds` 가 그날 몇 번째 이벤트인지로만 시각을 정한다(첫 이벤트 = 아침 칸). 장면이 정한 시각을 모른다.
  클래식 `m01` 은 아침 장면이라 드러나지 않았는데, 신규 시작 d1 은 둘이나 "새벽"이 핵심 설정이다.

**P1-3. "잠수 타서 식힐까" 결정을 내리는 곳에 소문이 안 보인다**
- 근거: `12_sc_leak_2_action.png` — 소문 30 인 회차의 행동 화면. 스탯 격자에 소문이 없고, "집에서 휴식" 설명은
  `config.json` 그대로 "스트레스를 줄이고 자존감을 회복한다"이며 `heat: -6` 은 어디에도 적혀 있지 않다.
- 설계 §5.1 이 정한 위치(홈·정산)는 지켰다. 하지만 같은 절이 말하는 핵심 결정("판을 키울까, 잠수 타서 식힐까")은 행동 화면에서 내린다.

  홈 게이지·정산 게이지만으로는 "60 박제 위기" 문턱에 다가가는 걸 하루 단위로 막기 어렵다.
- 제안: 행동 화면 스탯 묶음 아래에 compact 게이지, 휴식 카드에 "소문 −6" 표기.

### P2

- **P2-1. 운명 뽑기 결과를 알려 주지 않는다.** 운명을 누르면 시트가 닫히고 곧바로 introLine 말풍선만 들어간다(`04`). 무엇이 나왔는지(제목,
  "잠긴 이야기가 열렸다") 보여 주는 순간이 없다. 잠긴 시작이 나와도 플레이어는 그게 특별한 일인지 모른다.
- **P2-2. 잠긴 카드의 흐림이 그림 띠 밖으로 번진다.** `ImageFiltered` 를 자르지 않아 그림 아래 가장자리가 흰 안개처럼 본문으로 번진다
  (`02`, `03`, `14` 의 그림 아래 경계). 다크에서는 덜 보인다. `ClipRect` 로 감싸면 된다.
- **P2-3. 라이트 모드에서 카드 본문의 경계가 없다.** 카드 면(`surfaceContainerLow`)이 시트 배경과 거의 같아, 그림 아래 글자가 떠 보이고
  어디까지가 한 카드인지 흐릿하다(`01`, `02`). 다크(`15`)에서는 구분된다.
- **P2-4. 캐스트 소개가 시작과 따로 논다.** 마이크 켜진 새벽(먼저 다가오는 사람 소희·민재)으로 시작해도 캐스트 화면은 서연·지우·예은·다은 순서에
  클래식용 첫 대사 그대로다. 예은의 "혹시 너 우리 초등학교 6학년 3반 맞지?"는 축사 대참사(예은이 하객석 짝꿍) 회차라면 이미 본 사이와 어긋날 수 있다.
  (스크린샷은 sc_clip 회차 cast 화면, 저장본에는 포함 안 함 — 원본은 스크래치패드)
- **P2-5. 시트가 길어 운명 뽑기가 안 보인다.** 카드 6장 × 그림 띠(가로세로 2.2:1)라 운명 카드는 393pt 에서 약 4화면, 320pt 에서 약 6화면 아래다.
  설계가 운명 뽑기를 해금 동기로 쓰려 한다면 발견성이 낮다.
- **P2-6. 설계의 "2회차 이후 기본 선택(아직 안 해 본 시작 중 첫 번째)"이 없다.** 홈 시트(`13`)에는 강조·기본 선택이 없고, 관성대로 맨 위 클래식을 누르기 쉽다.
- **P2-7. 신규 시작 d1 에는 장면 그림이 없다.** 클래식 m01 은 큰 그림으로 열리는데 단톡 박제·축사는 글만으로 연다(`06` vs `07`/`08`).
  그림은 사용자가 만들기로 한 몫이라 결함은 아니지만, 그림이 들어오기 전에는 신규 시작의 첫인상이 클래식보다 약하다.

## 3. 확인하지 못한 것

- **실제 iOS 시뮬레이터·기기에서의 동작 전부.** 시뮬레이터 런타임이 없다. safe area(노치·다이내믹 아일랜드·홈 인디케이터) 아래 시트 상단·하단 여백,
  실제 시트 드래그·스크롤 관성, 햅틱·효과음, 광고·ATT 팝업과의 겹침, 로딩 시간은 못 봤다. → Xcode 에서 iOS 26.x 시뮬레이터 런타임 설치 후 R2 에서 재확인 필요.
- 시트 안 실제 그림(신규 4종 `*_d1`)이 들어왔을 때의 자르기(2.2:1). 지금은 classic `m01` 만 확인.
- 엔딩 화면 → "다음 판" 경로의 시트(`ending_screen.dart` 도 `showFor` 사용, 운명 고정 없음 — 여기서는 뒤로 가기 루프가 없어 재뽑기 문제는 없어 보이나 실행 확인 안 함).
- 진짜 2회차 상태: 홈 시험은 엔딩 앨범 1개를 직접 넣은 합성 상태라, "처음이라면" 배지가 함께 뜬 것(`isFirstOnboarding`)이 실제 2회차에서도 그런지 모른다.
- 다크 모드의 홈·정산 소문 게이지(라이트만 촬영), SE 크기의 홈 화면.
