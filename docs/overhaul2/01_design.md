## 0. 한 장 요약

- **문제**: 1~7일차가 회차마다 글자까지 똑같다. 메인 이벤트에 트리거가 없어서 언제나 나오고, 검증기가 같은 날 메인을
  둘 두지 못하게 막는다. 구조상 첫 주를 바꿀 방법이 없다.
- **해법 1. 시작 스토리 6종**: 클래식(태현의 치킨 내기) + 신규 5종. 각자 1~3일차 메인과 첫 분기(3갈래), 시작 보정,
  초반에 가까워지는 역할, 90~100일차 정산 장면을 갖는다.
- **해법 2. 자유 시스템 3종(최소 세트)**: ① 소문 지수(`heat`, GTA 수배 레벨) ② 파급 줄(`ifFlags`, 선택이 100일 내내
  대사에 남는다) ③ 의뢰(부업, GTA 사이드 미션, JSON 만으로).
- **엔진 변경은 작게**: 시작 스토리 로더와 적용(newGame), 메인 날짜 검증 키, 스탯 키 하나(`heat`), 줄·선택지 조건 필드
  두 개. 세이브 키 `mossol_save_v1` 은 그대로 두고 필드도 추가만 한다. 나머지는 전부 JSON 작업이다.
- **새 그림**: 꼭 필요한 것 5장(시작 카드 겸 1일차 장면). 권장 7장을 더하면 모두 12장, 약 1.4MB.
  움직이는 그림은 영상 대신 코드 연출로 처리한다.

### 1.2 왜 지루한가

1. **주인공의 처지가 하나다.** 평범한 모쏠과 코치 태현. 판돈은 치킨이다. 잃을 것이 없으니 긴장이 없다.
2. **첫 갈림길이 바로 합쳐진다.** D1 의 두 선택(프사 3택, 내기 3택)은 모두 같은 다음 장면으로 간다. 3일 동안 뒤에까지
   남는 분기는 `bet_doubled`/`bet_public` 하나이고, 그 결과는 90일 뒤에 나온다.
3. **오프닝 일상 풀이 얕다.** `d_open_*` 은 10개인데 한 판에 3~5개가 나온다. 두세 판이면 다 보고, 그중 셋은 m01 프사를
   전제로 한다(`d_open_story`·`d_open_pfp_who`·`d_open_app_match`).
4. **적이 없고, 공개된 위험도 없다.** 처음으로 판이 흔들리는 장면이 D20 `m08`(반전)이고, 라이벌은 D57 `m22` 에 나온다.
   첫 세션(15~20분) 안에는 갈등이 하나도 없다.
5. **구조상 바꿀 수 없다.** main 은 `trigger` 없이 `day` 만 맞으면 나오고, 검증기(`story_repository.dart` 의 main 날짜
   중복 검사)는 같은 날 main 을 선호(pref) 쪽별로만 허용한다. 지금 데이터 형식으로는 "다른 첫날"을 만들 수 없다.

**결론**: 콘텐츠를 더 넣는 것만으로는 안 되고 시작 축을 하나 새로 만들어야 한다. 그 축은 **시작 플래그**다. 메인 날짜
검증이 이 플래그를 이해하게 만들면 나머지는 JSON 으로 해결된다.

## 2. GTA 벤치마크를 이 장르로 옮기기

GTA 가 성공한 이유를 "자유" 한 단어로 줄이면 잘못 옮기게 된다. 여기서는 플레이어가 겪는 감각 다섯 가지로 나눈다.
① 내가 고른 처지에서 시작한다. ② 무엇을 먼저 할지 내가 정한다. ③ 세상이 내 난동을 기억하고 반응한다(수배).
④ 본 줄거리 밖에서 돈과 사건을 찾는다(사이드). ⑤ 나쁜 짓도 할 수 있지만 대가가 따른다.

| GTA 요소 | 본질 | 이 게임에서의 형태 | 판정 |
|---|---|---|---|
| 주인공 3명, 각자 다른 출발 | 첫 10분부터 다른 이야기 | **시작 스토리 6종**(§3). 주인공은 1명 그대로, 처지만 바뀐다 | 채택 |
| 미션 순서를 고르는 샌드박스 | 누구를, 무엇을 먼저 | 이미 있다(루트 5명 + 아침 행동 6개). 시작 스토리가 초반 가속 대상을 바꾸고 첫 분기가 노선을 정한다 | 강화 |
| 수배 레벨(별) | 난동의 누적, 숨으면 식는다 | **소문 지수 `heat`**(§5.1). 단톡 박제, 바이럴, 진상 짓으로 오르고, 잠수(휴식)·사과로 내린다 | 채택 |

| 악당 짓의 자유 | 해도 되지만 대가가 있다 | 진상 선택지(거짓 연기, 복수 저격, 사칭 묵인) → 소문, 신뢰, 기존 `fishing`·`pickup_fall` 엔딩과 이어짐 | 채택(콘텐츠) |
| 라이벌·적 | 맞설 대상 | 시작 스토리마다 비연애 조연 라이벌 1명(서진, 클립 계정, 신랑 친구 등) | 채택(콘텐츠) |
| 라디오·뉴스 풍자 | 세상이 나를 화제로 삼는다 | 소문이 높으면 하루 정산에 "동네 소문 한 줄" | 보류(P2) |

| 카지노·베팅 | 위험한 보상 | App Store 설문 "모의 도박 없음" 답을 바꿔야 해서 등급이 오른다. 치킨 내기는 친구 사이 농담에서 멈춘다 | 거절 |
| 차·상점 소비 경제 | 돈을 쓰는 재미 | `ceo` 엔딩(돈 500)과 하트 경제의 균형이 깨진다. 돈을 쓰는 곳은 지금의 데이트·스타일링이면 충분하다 | 거절 |
| 주인공 전환(GTA V) | 시점 교차 | 세이브 1개, 주인공 1명 구조. 시작 스토리가 회차 단위로 같은 감각을 준다 | 거절 |
| 아무에게나 자유롭게 톡 | 무한한 상호작용 | LLM 없음. 제한형 자유 입력(F, 기존)으로 충분하다 | 거절 |
| 술 게임 벌칙 | 아찔한 시작 | App Store 설문의 알코올 "드물게"(13+)를 넘을 위험이 있다. 벌칙은 술 없는 놀이(축사, 마이크)로 바꿨다 | 거절 |

**"자극"의 경계(작가 규칙)**: 드라마, 스캔들, 창피, 바이럴, 배신, 라이벌, 비밀까지만 쓴다. 성적 묘사, 유혈, 약물,
음주 놀이는 쓰지 않는다. CAST_BIBLE §0.3(집착·추적·통제를 로맨스로 쓰지 않는다)은 그대로 지킨다. 복수 노선에서도
전 썸 상대의 SNS 를 몰래 보는 장면은 **유혹으로만** 제시하고, 고르면 소문 지수와 진정성이 깎이는 대가를 단다.
신상 공개(실명, 학교, 주소)는 "정체 추리"라는 농담 수준까지만 쓴다.

## 3. 시작 스토리 6종

### 3.0 공통 규칙

- **구성**: 클래식 1(기존) + 신규 5. 신규 5종이 역할 다섯(선배·알바·소개팅·온라인·동창)을 하나씩 가속하고,
  히든 트레이너는 "환승 목격"의 C 갈래가 가속한다. 모든 시작은 선호 f/m 에서 똑같이 동작한다. 이름은
  `{char:seoyeon,jeongwoo}` 처럼 이미 있는 쉼표 목록 문법으로 부른다(text_template.dart). 이 때문에 레코드를
  쪼갤 필요가 없다.
- **플래그**: 신규 시작은 `start_alt` 와 자기 id(예: `sc_leak`)를 세운다. 클래식 장면은 `notFlags: ["start_alt"]` 로만
  막는다. 이렇게 하면 이미 진행 중인 세이브(플래그 없음)는 자동으로 클래식이 되므로 이전 작업이 필요 없다.
- **이벤트 이름**: `<id>_d1`·`_d2`·`_d3`(main, `trigger.flags: [<id>]`, day 1·2·3), 첫 분기 결과 `<id>_d1a/b/c`(daily,
  `day [0,0]` 로 잠그고 `next` 로만 진입), 일상 채움 `<id>_open_1·2`(daily, day [1,3]), 정산 `<id>_settle`(day [90,100]).
- **치킨 내기는 모든 시작에 남긴다.** D7 `m_week1`, D11 `m05`, D39 `m15`, D95 `m37`, 엔딩 `forever_solo` 가 내기를
  전제로 하기 때문이다. 신규 시작은 D2 메인의 선택지가 `next: d_open_bet` 으로 내기를 연다. 판돈 대사는 파급 줄(§5.2)로
  시작마다 다르게 쓴다. 클래식에서는 내기가 이야기의 전부이고, 신규 시작에서는 곁가지 농담이다.
- **태현의 브리핑(m_brief)** 은 클래식 전용이다. 신규 시작은 D3 메인의 모든 선택지가 `next: d_brief_alt` 로 이어진다.
  `d_brief_alt` 는 다섯 명을 `{char:…}` 로 소개하는 짧은 공용판이다. 시작마다 첫 두 줄만 `ifFlags` 로 바꾼다.
- **시작 보정 상한**(밸런스): 스탯 하나당 ±10 이내. 진정성은 −5 아래로 내리지 않는다(해피 엔딩 조건이 진정성 50 이상이고
  시작값도 50이다). 호감은 해당 역할 짝 두 id 에 +4 까지(r00 은 호감 15 이하에서만 나오고, D1~3 earlyAffection 배율이
  붙어도 15를 넘지 않는다). 시작 소문은 40 이하(소문 위기가 60부터 시작한다).
- **보정 수치는 전부 `[PLACEHOLDER]`** 이다. §7 시뮬레이션(시작 6종 × 전략 14 × 시드 2000)으로 확정한다.
- **루트 진행 플래그는 세우지 않는다.** `*_met`, `jiwoo_intro` 같은 ROUTE_ORDER 플래그는 기존 이벤트만 세운다.
  시작 스토리는 `sc_*` 플래그와 호감·신뢰만 건드린다. 그래야 route_order_test 와 deadlock_test 의 불변식이 유지된다.

### 3.2 `classic` — 치킨 열 마리 (기존 유지)

- **로그라인**: 태현이 "100일 안에 연애 못 하면 치킨 열 마리"를 걸었다. 증인은 친구 단톡 일곱 명이다.
- **왜 남기나**: 튜토리얼 역할이 가장 좋다(m02 답장 속도 미니게임, m_brief 의 다섯 명 소개). 처음 하는 플레이어에게
  "처음이라면" 배지로 권한다.
- **보정·플래그**: 없음(기존 `bet_*`). 루트는 지금처럼 균등 무작위다.
- **작은 강화(선택)**: `d_open_bet_2` 의 "다들 지켜봐 주세요"(`bet_public`)에 소문 +8. 증인 단톡이 첫 소문 공급원이 된다.
  여기 외에는 손대지 않는다. opening_test 가 고정하는 동작이 이 시작이다.
- **보상**: 기존 `d_bet_settle` 3종(D90~100).

### 3.3 `sc_leak` — 단톡 박제

### 3.6 `sc_swap` — 환승 목격

### 3.7 `sc_ghost` — 새벽 3시의 나

- **훅**: 아침에 모르는 사람의 톡이 와 있다. "어제 새벽 3시에 써 주신 시, 아직도 생각나요." 나는 시를 쓴 적이 없다.

## 4. 고르는 방법: 시작 선택 화면

### 4.1 원칙

- **이야기 안에서 고른다.** 인트로는 이미 태현과의 대화다. 여기에 질문 하나만 넣는다.
  태현: "갑자기 왜. 무슨 일 있었지?" → 카드 시트가 열린다. 카드 하나하나가 주인공의 대답이다.
- 카드를 고르면 그 카드의 `introLine` 이 내 말풍선으로, `introReply` 가 태현의 반응으로 들어간다.
  클래식은 "그냥. 올해는 다르게 살고 싶어" → "그럼 내기하자"다.
- **2회차 이후**(홈의 새 게임 시트)에는 같은 카드 시트가 첫 단계로 뜬다. 그다음은 지금처럼 성별, 선호, 이름, MBTI 순서다.
  시작이 가장 큰 결정이고 선호 선택에 영향을 주지 않으므로 맨 앞에 둔다.

### 4.2 인트로 순서 (1회차)

`타이틀 → 알림 미리보기(태현) → "한다/일단 해볼게" → **[시작 카드]** → 이름 → 선호 → 캐스트 → newGame(preference, start)`

- 고칠 곳은 `IntroScreen` 의 단계 하나(`IntroStep.start`)와 `_start(preference)` 에 시작 id 를 넘기는 것이다.
  뒤로 가기(`_revertToLastQuestion`)는 시작 단계에도 같은 규칙으로 적용한다.
- MBTI 는 지금처럼 D4 단톡에서 묻는다(모든 시작 공통). 단톡 대사에 `ifFlags` 로 한 줄을 더한다. 예: `sc_clip` 이면
  "신입 단톡에서도 그 클립 얘기 중".

### 4.3 카드 (세로 스크롤 6장)

| 요소 | 내용 |
|---|---|
| 그림 | 1일차 장면 그림(§6). 클래식은 기존 `assets/scenes/m01.webp` |
| 제목·훅 | "단톡 박제" / "고백 연습을 알바 단톡에 보냈다" |
| 태그 | 톤 2개 + 자극도 고추 1~3개(텍스트 칩. 이모지는 쓰지 않는다) + "먼저 다가오는 사람: {char:daeun,haneul}" |
| 배지 | "처음이라면"(클래식, 1회차) · "새로 열림" · "본 적 있음(엔딩 n개)" |
| 잠김 | 그림을 흐리게 하고 자물쇠 표시, "엔딩 1개를 보면 열려요". 탭하면 훅 한 줄만 보여 준다(호기심 유발) |

- **해금** `[PLACEHOLDER]`: 처음부터 4종(클래식·단톡 박제·축사 대참사·마이크). `sc_swap` 은 엔딩 1개, `sc_ghost` 는 엔딩 2개.

- 2회차 이후 기본 선택은 "아직 안 해 본 시작 중 첫 번째"다. 매번 클래식으로 돌아가는 관성을 끊는다.

### 5.2 F2 — 파급 줄 `ifFlags` / `ifNotFlags` (선택이 세상에 남는다)

**목적**: D1 의 선택이 D7·D26·D57·D95 에 대사로 되돌아오게 한다. 이벤트를 쪼개지 않는다. GTA 의 "세상이 기억한다"를
가장 싸게 옮기는 방법이다.

| 필드 | 붙는 곳 | 동작 |
|---|---|---|
| `ifFlags: [..]` | `Line`, `Choice` | 모든 플래그가 있을 때만 보인다 |
| `ifNotFlags: [..]` | `Line`, `Choice` | 하나라도 있으면 숨는다 |

- **잠금이 아니라 숨김이다.** `require.flags` 는 잠금 문구가 플래그를 설명하지 못해서 금지돼 있다(README). 숨김은 그 문제가
  없다. 진상 선택지("서진 스토리 몰래 보기")는 그 노선에 있는 사람에게만 나타난다.
- 구현: `viewFor` 가 이미 MBTI 조건으로 줄과 선택지를 거른다(`forMbti`). 같은 자리에 플래그 거르기를 하나 더 한다.
  자유 입력 매처는 거른 뒤의 선택지를 보므로 손댈 필요가 없다.
- 검증기 규칙: 어떤 이벤트든 `ifFlags`·`ifNotFlags` 가 없는 선택지가 **2개 이상** 있어야 한다(어떤 플래그 조합에서도
  선택지가 1개 이하로 줄지 않게). 플래그 이름은 어디선가 `setFlags` 로 세워져야 한다(오타 방지).
- 첫 적용처(JSON): `d_open_bet`(판돈 대사 5벌), `d_brief_alt`(첫 두 줄), `m_mbti_chat_*`, `m03`, `m08`, `m10`, `m21`, `m22`,
  `m24`, `m37`, `m_week1`(내기 이유 한 줄). 모두 줄을 **더하기만** 한다.

### 6.3 움직이는 그림(GIF·루프 영상)에 대한 의견

**결론: 영상은 넣지 않는다. 움직임은 코드로 만들고, 정 원하면 움직이는 WebP 2장까지만 쓴다.**

| 고려 | 판단 |
|---|---|
| 기술 | Flutter `Image.asset` 은 움직이는 GIF·WebP 를 패키지 없이 재생한다. 루프 영상(mp4)은 `video_player` 플러그인, 네이티브 코드, 자동재생·음소거·백그라운드 처리가 필요해 이번 범위로는 과하다 |
| 용량 | 정지 장면 ~120KB 대 2초짜리 720px 움직이는 WebP 0.5~1.5MB. 지금 에셋이 ~42MB(엔딩 15MB, 사진 11MB)라 여유가 크지 않다 |
| 제작 | 그림은 사용자가 이미지 생성 도구로 만든다. 움직이는 그림은 영상 생성 도구가 필요하고, 웹툰 화풍 일관성과 얼굴 금지 규칙을 지키기 어렵다 |
| 심사 | App Store 는 움직이는 이미지를 문제 삼지 않는다. 등급에도 영향이 없다. 다만 "동작 줄이기" 설정을 따라야 한다 |
| 효과 | 이 개편에서 자극은 "알림이 쏟아진다", "읽음 숫자가 오른다", "소문 게이지가 터진다"에서 나온다. 이건 그림이 아니라 **UI 움직임**이고, 코드로 만들면 더 선명하고, 한국어 글자도 넣을 수 있고, 용량은 0이다 |

**코드 연출로 할 것**(UI 작업, 용량 0)
1. 장면 카드의 Ken Burns(6초에 걸쳐 1.00→1.04 확대 + 약간 이동). 모든 장면 그림이 정지 그림인 채로 살아 보인다.
2. 알림 폭탄: `sc_leak`·`sc_clip` D1 에서 알림 카드(기존 `notification_card.dart`)가 0.15초 간격으로 쌓이고 `msg_in` 소리가 난다.
3. 읽음 카운터 증가(1→4→9). 대사 `wait` 에 맞춘다.
4. 소문 게이지 칸이 켜질 때 빛과 `mediumImpact`.

**그래도 움직이는 그림을 쓴다면(선택, 최대 2장)**: `sc_speech_d1` 부케가 날아가는 루프와 `sc_clip_d1` 마이크 불빛이
깜빡이는 루프. 각각 2초, 12fps, 600KB 이하로 하고, 정지 그림을 폴백으로 둔다. 동작 줄이기가 켜져 있으면 첫 프레임만
보여 준다.

## 7. 밸런스·테스트·작업 순서

### 7.1 "망가짐"의 정의 (플레이테스트 전에 정해 둔다)

- 시작마다 전략별 해피 비율이 README 목표(first ≤6%, random ≤5%, focus 72~80%, focus+hint 85~92%, statGrow ≤85%)를
  **±3%p 이상 벗어나면** 망가진 것이다. 가장 위험한 경우는 가속받은 역할을 focus 봇이 고를 때다.
- 가속 역할의 r00 이 D1~3 에 나오지 않으면 망가진 것이다(호감 +4 때문에 15를 넘는 경우).
- 어느 시작에서든 D1~3 main 이 0개 또는 2개 이상이면 망가진 것이다(B3·B6 테스트).
- 소문 위기가 D1~7 에 나오거나, 소문 엔딩이 해피를 빼앗으면 망가진 것이다.
- 도달 가능 엔딩(시드 2000)이 26개에서 줄어들면 망가진 것이다. 소문 엔딩 2개가 늘어나 28개가 목표다.

### 7.4 열린 질문 (사용자 결정 필요)

1. 1회차에 시작 4종을 열지, 클래식만 열지. 이 문서는 4종을 권한다. 불만의 핵심이 첫인상의 동일함이기 때문이다.
2. 운명 뽑기가 잠긴 시작을 뽑으면 영구 해금할지. 이 문서는 "이번 회차만"을 권한다. 메타 필드가 늘지 않는다.
3. 소문 게이지를 클래식 회차에도 보여 줄지. 이 문서는 "소문이 1 이상일 때만"을 권한다.
