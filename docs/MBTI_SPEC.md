# MBTI 분기 스펙

> 2026-09-22 결정: **깊은 분기**. 플레이어 MBTI 4축(E/I, S/N, T/F, J/P)마다 주요 장면이 달라지고,
> MBTI 전용 엔딩이 있다. 이 문서가 엔진·UI·대본 작업의 계약이다. 필드 이름·의미를 바꾸려면 이 문서부터 고친다.

## 0. 원칙

1. **MBTI는 맛이지 자물쇠가 아니다.** 어떤 MBTI(모름 포함)든 모든 캐릭터의 해피 엔딩에 도달할 수 있다.
   MBTI로 갈리는 것은 대사·선택지·장면이고, 난이도 차이는 작다(§4 밸런스 기준).
2. **모름(null)이 정상 경로다.** MBTI를 건너뛴 플레이어도 빈칸 없이 자연스러운 이야기를 본다.
   MBTI 조건이 붙은 줄·선택지에는 항상 조건 없는 대체가 있어야 한다(§2.5 검증).
3. **고정관념 조롱 금지.** "T라서 공감 못 함" 같은 비하 농담은 쓰지 않는다. 성향은 **그 사람이 좋아하는 방식**으로 그린다
   (I = 혼자 충전하는 시간이 소중함, T = 해결책으로 마음을 표현함).
4. 캐릭터 MBTI는 **설정 표시 + 궁합 + 대사 소재**다. 캐릭터 성격 자체를 MBTI에 맞춰 바꾸지 않는다(이미 CAST_BIBLE로 확정).

## 1. 데이터

### 1.1 캐릭터 MBTI (`characters.json`의 `mbti`)

한 쪽 안에서 16유형이 겹치지 않고, 짝(같은 role)끼리도 다르다.

| role | 여성 캐릭터 쪽 | 근거 | 남성 캐릭터 쪽 | 근거 |
|---|---|---|---|---|
| senior | 서연 **INTJ** | 무심한 척 계산된 한 방, 정색 유머 | 정우 **ISFJ** | 챙기는 회장님, 서툰 표현 |
| parttime | 다은 **INFP** | 영수증 뒤에 그림, 멍한 무표정 속 감수성 | 하늘 **ESFP** | 국밥·마감·윙크, 지금 이 순간 |
| blinddate | 지우 **ENTJ** | 변호사, 칼답장, 주도권 | 승현 **ISTJ** | 좋으면 좋다고 말함, 원칙·직진 |
| online | 소희 **ESTP** | 샷콜, 즉흥, 큰 목소리 | 민재 **INTP** | 새벽 게임, 얼굴 비밀, 딴생각 |
| classmate | 예은 **ESFJ** | 흑역사까지 다 기억, 서운함 표현 | 건우 **ENFP** | 장난기, 말없이 갔다 돌아옴 |
| trainer(히든) | 유나 **ENFJ** | 칭찬으로 한 개 더, 사람을 키움 | 도윤 **ESTJ** | 허리부터 챙기는 루틴, 책임감 |

### 1.2 플레이어 MBTI

- 기기 설정: `PlayerMeta.mbti` (`"INTJ"` 같은 대문자 4글자, 또는 null=모름/건너뜀).
- 판 상태: `GameState.mbti` — **새 게임 시작 때 PlayerMeta에서 복사**해 세이브에 저장한다. 판 도중 설정을 바꿔도
  진행 중인 판은 그대로(분기 일관성), 다음 새 게임부터 반영. 설정 화면 문구에 이 점을 적는다.
- 예전 세이브는 `mbti` 없음 → null.

### 1.3 조건 문법 — `mbti` 글자열

`"mbti": "I"`, `"mbti": "NF"`, `"mbti": "ESTJ"` — 적힌 **모든 글자**가 플레이어 MBTI에 있어야 참.
플레이어가 null이면 **항상 거짓**. 글자는 E I S N T F J P만, 같은 축 두 글자(`"EI"`) 금지(검증 에러).

쓰는 곳:

| 위치 | 필드 | 의미 |
|---|---|---|
| 이벤트 `trigger` | `mbti` | 이 이벤트는 해당 성향 플레이어에게만 나온다 |
| 이벤트 `trigger` | `noMbti: true` | MBTI 모름(null) 플레이어에게만 나온다(대체 장면용) |
| 줄(`lines[]`, `reply[]` 등의 객체 줄) | `mbti` | 해당 성향일 때만 보이는 줄 |
| 줄 | `noMbti: true` | 모름일 때만 보이는 줄 |
| 선택지 | `mbti` / `noMbti` | 해당 성향일 때만 보이는 선택지 |
| 엔딩 `when` | `mbti` | 해당 성향일 때만 성립 |
| 엔딩 `when` | `compat: [min, max]` | 이 엔딩 `character`와 플레이어의 궁합 점수 범위(§1.5) |
| 줄·선택지 | `compat: [min, max]` | 이 이벤트 `character`와의 궁합 점수 범위. 캐릭터 없는 이벤트에선 검증 에러 |
| 엔딩 `when`·이벤트 `trigger` | `flagsAtLeast: {"n": 2, "of": ["a","b",…]}` | 목록 중 n개 이상 플래그가 있으면 참 |

문자열 줄(`"reply": ["…"]`)은 조건을 못 단다. 조건이 필요하면 객체 줄 `{"who":"them","text":"…","mbti":"I"}`.

### 1.4 텍스트 치환

- `{mbti}` → 플레이어 MBTI(예: `INFP`). **null이면 이 자리 문장 전체를 쓰지 말 것** — `{mbti}`는 반드시
  `mbti` 조건이 붙은 줄·선택지 안에서만 쓴다(검증 에러).
- `{mbti|대체어}` → null이면 대체어.
- 캐릭터 자기 MBTI는 대사에 그냥 적는다(`"나 INTJ야."`).

### 1.5 궁합

`compat(player, character)` → 0~4 정수. player null이면 **2(보통)**.

```
score = (S/N 같음 ? 2 : 0) + (E/I 다름 ? 1 : 0) + (J/P 다름 ? 1 : 0)
```

- 4 = 천생연분 (S/N 같고 E/I·J/P 다름), 3 = 잘 맞음, 2 = 보통, 1 = 노력형, 0 = 정반대.
- 표시: 하트 5칸 중 `score + 1`칸, 라벨 `천생연분 · 잘 맞아요 · 무난해요 · 노력하면 · 정반대`.
- **효과(작게)**: 그 캐릭터 호감도 **양수** 변화에 배율 `config.mbti.compatMultiplier[score]`
  (초안 `[0.95, 0.98, 1.0, 1.03, 1.06]`). 음수 변화에는 적용 안 함. 초기 호감 보너스는 없음(첫인상은 대사로).

### 1.6 엔딩

- **천생연분 엔딩 12개** (`<id>_destiny`): 캐릭터별. 조건 = 그 캐릭터 해피 엔딩 조건 + `compat: [4,4]` +
  route 성향 장면 플래그 2개 이상(§3.2). priority는 해피보다 높게(해피 200이면 210). tier `happy`.
  에필로그에는 두 사람 MBTI가 맞물리는 장면이 들어간다. 앨범 60개(쪽별 36개).
- **기질 에필로그**: 해피 엔딩 12개와 공용 엔딩 12개에 `epilogueMbti` 추가 가능 —
  `{"NT": "…", "NF": "…", "SJ": "…", "SP": "…"}`. 플레이어 기질에 맞는 문단을 **기본 에필로그 뒤에 한 줄 덧붙인다**.
  null이면 덧붙이지 않는다. 기질 판정: N+T=NT, N+F=NF, S+J=SJ, S+P=SP.

## 2. 엔진·UI

### 2.1 온보딩
성별 → 이름 → **MBTI** → 캐스트 소개.
- 4축 토글 두 칸씩(E/I, S/N, T/F, J/P). 네 축을 다 고르면 `다음`.
- `잘 몰라요` → **4문항 간이 테스트**(축마다 상황 질문 하나, 답 두 개). 끝나면 결과를 토글에 채워 보여 주고
  "대충 맞아요?"로 수정 가능. 간이 테스트임을 한 줄로 밝힌다.
- `건너뛰기` → null.
- 디버그 갤러리에 MBTI 단계 미리보기.

### 2.2 표시
- 캐스트 소개 카드: 이름 옆 MBTI 칩, 아래 궁합 하트 + 라벨(플레이어 null이면 궁합 줄 숨김).
- 히든 미공개 캐릭터는 MBTI도 `????`.
- 설정: `내 MBTI` 항목(수정·지우기, "다음 새 게임부터 적용").

### 2.3 게임 진행
- 줄·선택지 필터는 표시 직전에 한 번(이름 치환과 같은 층). 필터 후 선택지가 1개 이하가 되면 **검증에서 막는다**(§2.5).
- 궁합 배율은 `effects.dart` 호감 계산에 합류(early affection·crit 이후 곱).
- `GameState.mbti` 저장·로드, 예전 세이브 호환.

### 2.4 시뮬레이터
- `sim_balance_test.dart`에 `MBTI=INTJ|all|none` 옵션. `all` = 16유형 + null 17회를 돌려 표로.
- `route_order_test.dart` 도달성은 16유형 + null 각각에서 dead end 0.

### 2.5 검증 (`story_repository.validate`)
모든 이벤트에 대해, 플레이어 MBTI 17가지(16 + null) 각각으로:
- 필터 후 선택지 ≥ 2 (원래 선택지가 1개인 이벤트는 1 유지).
- 필터 후 `lines`가 1줄 이상.
- 모든 선택지의 reply가 필터 후에도 0줄이 되지 않음(원래 비어 있던 건 제외).
- `{mbti}`(대체어 없는)가 `mbti` 조건 없는 줄·선택지에 있으면 에러.
- 잘못된 글자, 같은 축 두 글자 에러.

## 3. 대본

### 3.1 공통 메인 이벤트 (events_main.json)
**축마다 3개 이상, 총 12개 이상**의 메인 이벤트에 성향 분기를 넣는다(양쪽 변형 `_f`/`_m` 모두).
분기 방식: 기존 줄 사이에 `mbti` 줄 2~4줄 삽입 + 그 성향만의 선택지 1개 추가(기존 선택지는 유지).
예: 주말 약속 이벤트 — E에게는 "사람 많은 데 가자"는 제안이, I에게는 "조용한 데"가 먼저 온다.

### 3.2 캐릭터 route 성향 장면 (12명 × 4축 = 48장면)
캐릭터마다 route 이벤트 중 4개(권장: r03~r05 중 1, r06~r08 중 1, r09~r11 중 1, r12~r14 중 1)를 골라
축 하나씩 배정하고:
- 양쪽 글자 각각에 **그 캐릭터와 부딪히거나 맞물리는 줄 3~5줄**(`mbti:"E"` / `mbti:"I"`), null용 `noMbti` 줄은
  기존 줄로 충분하면 생략 가능.
- 양쪽 글자 각각 **전용 선택지 1개**(`mbti` 조건). 전용 선택지를 고르면 플래그 `<id>_mbti_<axis>`
  (axis = `ei`·`sn`·`tf`·`jp`) 설정 + 평소 좋은 선택지 수준 효과. 전용 선택지는 그 캐릭터 MBTI와의 관계를 반영
  (같은 글자면 "통한다", 다른 글자면 "다르지만 끌린다"를 대사로).
- 천생연분 엔딩 조건의 "성향 장면 플래그 2개 이상"은 `anyFlags` 대신 **플래그 4개 중 2개**가 필요하므로
  엔딩 `when`에 `flagsAtLeast: {"n": 2, "of": [...]}`를 쓴다(엔진이 지원).

### 3.3 MBTI 대화 모먼트 (캐릭터당 1개, 12개)
`events_moments.json`이 아니라 각 route 파일에 추가. id `<id>_mbti_talk`. trigger `flags: ["<id>_met"]`, day ≥ 8.
캐릭터가 "너 MBTI 뭐야?"를 묻는 장면. 플레이어 16유형 × 대사를 다 쓰지 않는다 — **캐릭터 MBTI와의 궁합 점수(0~4)별 반응**을
`mbti` 조건 조합으로 쓰기 어렵기 때문에, 엔진이 제공하는 줄 조건 `compat: [min,max]`(이 이벤트 캐릭터 기준)를 쓴다.
null 플레이어에게는 "몰라? 그럼 내가 맞혀 볼게" 류의 `noMbti` 줄.
→ 줄·선택지 조건에도 `compat`을 허용한다(§1.3 표에 추가된 것으로 본다).

### 3.4 문장 규칙
CAST_BIBLE §0.3 대사 규칙, reply 60자·3줄 한도(reply_coverage_test), `{name…}` 치환 규칙을 그대로 따른다.
새 한글이 들어가면 `python3 tool/subset_fonts.py`를 다시 돌린다.

## 4. 밸런스 기준
- 16유형 + null 각각: focus 전략 해피율이 지금 목표 범위(72~80%) 안, 유형 간 최대-최소 차이 ≤ 8pp.
- 천생연분 엔딩: 궁합 4인 유형이 focus+hint로 그 캐릭터를 공략하면 40~70%.
- 궁합 0 유형도 해피 엔딩 가능(focus 해피율 ≥ 65%).
