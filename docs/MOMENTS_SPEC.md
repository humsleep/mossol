# 형식을 깨는 이벤트 ("모먼트") 데이터 규격 (2026-09-19)

실기기 QA: "이틀 동안 '이벤트 4개 → 정산 → 룰렛 → 행동' 리듬이 똑같아 2일차부터 작업처럼 느껴진다.
하루 중 하나는 형식이 다른 이벤트(전화, 사진, 상대가 먼저 거는 톡)가 있어야 '오늘은 뭐지'가 생긴다."

엔지니어와 작가가 **이 문서만 보고 동시에** 작업한다. 형식을 바꿀 일이 생기면 이 문서를 먼저 고친다.

## 1. 새 필드 (전부 선택, 없으면 지금과 똑같이 동작)

### 1.1 이벤트 `format`: `"chat"`(기본) | `"call"`
- **`"call"` — 상대가 먼저 거는 전화.** 이벤트 화면이 채팅 대신 **걸려 오는 전화 화면**으로 시작한다.
  - 1단계(수신): 큰 아바타(이니셜 + 캐릭터 강조색), 이름, "전화가 왔어요", 울림 애니메이션(동작 줄이기면 정지),
    버튼 두 개 `받기` / `거절`. 진동·소리는 없다.
  - `거절` → 이 이벤트에서 `"decline": true` 인 선택지를 그대로 고른 것과 같다(효과·반응·결과 패널 동일).
    반응은 채팅 말풍선으로 뜬다(예: 부재중 뒤 온 톡 "바빠? 나중에 연락해").
  - `받기` → 2단계(통화 중): 상단에 통화 시간 타이머(00:00부터 올라감), 대사는 **자막형**으로 보여 준다
    (`them` 은 크게 가운데, `me` 는 작게 오른쪽, `narr` 는 기울임). 대기 줄(`wait`)은 "…(침묵)" 으로 표시.
    대사가 끝나면 평소처럼 선택지 패널이 뜨되 **`decline` 선택지는 숨긴다**. 선택 → 반응(자막) → 결과 패널.
  - 검증: `call` 이벤트는 `character` 필수, `decline: true` 선택지가 정확히 1개, 그 선택지에 `require`·`minigame`·`chance` 금지.
    `decline` 이 아닌 선택지가 1개 이상.
- 미니게임은 통화 중 선택지에도 붙일 수 있다(`call_rhythm` 이 특히 어울린다).

### 1.2 이벤트 `preview`: 문자열 (40자 이내)
- **상대가 먼저 보낸 톡 알림.** 이벤트 화면에 들어가기 직전, 잠금화면 알림처럼 생긴 카드가 위에서 내려온다
  (아바타, 이름, `preview` 문장, "지금"). 탭하면(또는 1.8초 뒤 자동으로) 대화가 열린다.
- `chat` 이벤트에만 쓴다. 첫 줄은 보통 `them` 이고, `preview` 는 그 첫 줄과 같거나 요약이다.
- 캐릭터가 없는 이벤트는 `lines` 첫 `them` 줄의 `name`(예: 태현)을 알림 이름으로 쓴다. 둘 다 없으면 무시.

### 1.3 대사 줄 `photo`: 사진 메시지
```json
{"who": "them", "photo": {"icon": "cafe", "caption": "창가 자리 잡았어"}, "text": "여기 올래?"}
```
- 말풍선 대신 **사진 카드**(4:3, 둥근 모서리). 실제 이미지는 없다. 캐릭터 강조색 그라데이션 위에 큰 아이콘과
  `caption`(사진 속 장면 설명, 20자 이내)을 얹어 "사진처럼" 보이게 한다. `text` 가 있으면 카드 아래 말풍선으로.
- `icon` 은 다음 중 하나: `cafe`, `food`, `sky`, `night`, `sea`, `selfie`, `pet`, `book`, `gym`, `game`,
  `music`, `flower`, `street`, `ticket`. 모르는 값이면 `photo` 기본 아이콘.
- `who` 가 `me` 면 오른쪽 정렬(내가 보낸 사진). 반응(`reply` 등)에도 쓸 수 있다.

### 1.4 선택지 `decline`: true — 1.1 참고.

## 2. 등장 빈도 (엔진)
- `format: "call"` 이거나 `preview` 가 있거나 `photo` 줄이 있는 이벤트를 **모먼트**라 부른다.
- `planDay` 는 마지막 모먼트가 2일 이상 전이면, 그날 후보 중 모먼트의 가중치를 3배로 올린다.
  `GameState.lastMomentDay`(세이브 호환: 없으면 0) 를 새로 둔다.
- 1일차에는 강제하지 않는다(오프닝 흐름 보존). 3일차부터 적용.

## 3. 콘텐츠 파일
- 새 파일 `assets/story/events_moments.json`(`StoryBundle.eventFiles` 에 추가). 레이어는 `route`(캐릭터 전용)
  또는 `daily`. id 접두사 `mo_`.
- 모든 선택지는 기존 규칙대로 `reply`(성공), 확률·미니게임이면 `failReply` 필수. 반응 최대 3줄, 줄당 60자.
- 기존 이벤트 규칙(성별 중립, 12+, 실존 브랜드 금지, `@top` 사용법)은 `docs/STORY_CLEANUP.md` 공통 정책을 따른다.

## 4. 구현 메모 (엔지니어, 2026-09-19) — 규격이 정하지 않은 부분의 결정
- **통화 중 대기 줄(`wait`)**: 카운트다운·자존감 −1·광고 건너뛰기가 없다. `"…(침묵)"` 을 띄우고 **2초** 멈춘 뒤
  다음 줄로 간다. `wait` 숫자는 통화에서는 쓰이지 않는다(채팅에서는 지금처럼 초 단위 대기).
- **`decline` 은 `call` 이벤트에만** 쓸 수 있다. chat 이벤트에 있으면 검증기가 거부한다.
- **`preview` 는 `call` 이벤트에 있으면 검증기가 거부한다**(1.2 "chat 이벤트에만").
- **모먼트 판정의 `photo` 줄**은 `lines` 와 반응(`reply`/`failReply`/`critReply`) 모두를 본다.
- 모먼트 선택이 적용되면(거절 포함) 그날이 `lastMomentDay` 가 된다. 되돌리기(광고)로는 되돌리지 않는다.
- 가중치 보정은 일상·루트(고른 캐릭터 후보 안)·히든 추첨 모두에 걸린다. 루트의 **캐릭터 선택**(호감 순)과 위기는 그대로.
- 빈 `preview`(공백뿐)는 없는 것으로 본다. 알림 이름을 못 정하면(캐릭터도 `them` 줄 `name` 도 없음) 알림 없이 바로 대화.
- 이벤트를 처음부터 볼 때만(대사 0줄 공개, 선택 전) 수신 화면·알림을 띄운다.
