# 07. 제한형 자유 입력 — 설계 (OVERHAUL_PLAN §2F 확정안)

테스터 질문: "채팅으로 직접 입력하게 해서 스토리를 이어가게 할 수 있어?"
답: **된다. 단, 문장을 '이해'하는 게 아니라 '분류'한다.** 플레이어가 친 문장을 기기 안에서 그 이벤트의 기존 선택지 하나로
매핑하고, 내 말풍선에는 **친 문장 그대로** 남긴다. 상대 반응·효과·다음 이벤트는 매핑된 선택지의 것. LLM·서버 없음(ROADMAP §3).

데이터 사실 (2026-09-23): 이벤트 447, 선택지 1,527. 선택지 수 3개 322 · 4개 57 · 5개 61 · 그 외 7. `require` 214 ·
`minigame` 191 · `chance` 85 · `mbti` 게이트 132 · `decline`(전화 거절) 14. 선택지 문구의 약 40%는 **말이 아니라 행동**
("안 누른다", "규칙대로 계속한다", "(조용히 캡처하고 모른 척한다)")이다 — 매퍼는 "무슨 말을 했나"가 아니라 **"어느 쪽 태도인가"**를 맞혀야 한다.

## 1. 매칭 모델 (Dart, 순수 함수, ML 의존 없음)

파일: `lib/engine/free_input.dart` — `FreeInputMatcher.match(String input, List<ChoiceView> visible, {bool inCall}) → MatchResult`.
UI·컨트롤러에 의존하지 않아 `flutter test` 로 그대로 돈다. 후보는 **`GameController.choices`(MBTI·궁합으로 걸러진 보이는 선택지)** 뿐이고,
통화 중이면 `decline` 선택지는 후보에서 뺀다(끊기는 통화 화면 버튼이 담당).

### 1.1 정규화 `norm(s)`
1. NFC, 앞뒤 공백 제거, 라틴 소문자화. 2. 반복 압축: `ㅋ{3,}→ㅋㅋ`, `ㅎ{3,}→ㅎㅎ`, `[ㅠㅜ]{3,}→ㅠㅠ`, `!{2,}→!!`, `\?{2,}→??`, `[.…]{2,}→…`.
3. 스타일 신호를 먼저 뽑고(§1.2) 4. 문장 부호·공백·이모지를 뺀 **본문**을 만든다. 형태소 분석기 없음 — 본문의 **음절 2-gram 집합**만 쓴다.

### 1.2 입력 특징 `InputFeatures`
| 특징 | 규칙 | 값 |
|---|---|---|
| `polite` | 본문 끝이 `요·니다·세요·죠·습니까·게요` 또는 `씨·선배님·님` 포함 → +1 / 끝이 `어·아·야·지·냐·니·자·래·게·다` → −1 / 그 외 0 | −1·0·+1 |
| `question` | `?` 포함 또는 끝이 `냐·니·까·나·나요·어?·야?·죠?` | bool |
| `lenBucket` | 본문 길이 ≤4 / 5~15 / 16+ | 0·1·2 |
| `emo` | `ㅋㅋ·ㅎㅎ`=joke, `ㅠㅠ·ㅜㅜ`=sad, `!!`=excited, `…`=hesitant, `♥·❤·하트·💕`=love | 집합 |
| `action` | `(`로 시작하거나 끝이 `ㄴ다·는다·한다·했다`(서술형) | bool |
| `tags` | §1.3 의도 사전에 걸린 태그 | 집합 |

### 1.3 의도 태그 사전 (전역 하나, `lib/engine/free_input_lexicon.dart`)
12개 태그. 각 태그에 부분 문자열 30~60개. 입력·선택지 문구·반응 줄 모두 같은 사전으로 태그를 뽑는다.
```
refuse   싫 안돼 안 해 못 해 아니 됐어 됐다 괜찮아요(거절) 사양 거절 안 할래 안 누 안 갈 안 봐
delay    나중 다음에 이따 담에 바빠 시간 없 오늘은 좀 보류 생각해볼
agree    응 어 그래 좋아 좋지 콜 ㅇㅋ 오케 넵 네 알았 할게 하자 가자 당연
honest   솔직 사실 진짜로 사실은 말할게 고백 숨기지 그대로 말 있는 그대로
ask      왜 뭐 누구 어디 언제 어떻게 무슨 ? 궁금 물어
joke     ㅋㅋ 드립 농담 장난 웃 개그 ㅋ
tease    놀 놀리 약올 뭐야 ㅋㅋ(question 동반) 어이없 헐
love     좋아해 보고 싶 같이 데려다 저녁 먹 손 설레 떨려 마음 사귀 심쿵 ♥
sorry    미안 죄송 잘못 사과 죄송해요
assert   내가 먼저 직접 지금 바로 말할게 하겠 할게(주어 내가) 나서
passive  모른 척 그냥 넘어 무시 조용히 가만 안 본 척 못 본 척 끄 알림 끈 냅둬 두자
care     괜찮아? 힘들 쉬어 조심 걱정 챙겨 무리하지 천천히 편하게
```
사전은 코드 상수다. 이벤트별 튜닝은 §2 의 `intent` 필드로 한다 — 사전을 이벤트 하나 때문에 건드리지 않는다.

### 1.4 선택지 서명 `ChoiceSignature` (런타임에 만들고 이벤트별로 캐시)
- `textGrams`: `c.say(choice.text)`(이름·MBTI 치환 뒤) 본문의 2-gram. 괄호·따옴표 제거.
- `replyGrams`: `reply`+`critReply`의 `them`/`narr` 줄 본문 2-gram 합집합(가중치 낮음 — 플레이어가 반응을 미리 알 리 없지만 "데려다 줄게" 같은 핵심 명사가 반응에 반복된다).
- `tags`: (a) 문구·반응 줄에서 사전으로 뽑은 태그 ∪ (b) **효과에서 유도한 태그** ∪ (c) JSON `intent` 필드(§2).
  효과 유도 규칙: `affection<0`→refuse·passive / `sincerity>0`→honest / `sincerity<0`→passive / `esteem>0`→assert / `stress<0`→passive·delay /
  `money<0`→love(한턱·데이트) / `reputation>0`→joke·agree / `decline`→refuse / `setFlags`에 `*_dm_first|*_confess*`→love.
- `style`: 문구의 `polite`·`question`·`lenBucket`·`action`(§1.2 규칙 그대로 적용).

### 1.5 점수
```
score(c) = 0.40·dice(in.grams, c.textGrams)          // 문구 유사도
         + 0.15·dice(in.grams, c.replyGrams)         // 반응 유사도
         + 0.35·jaccard(in.tags, c.tags)             // 의도 일치 (행동형 선택지의 주력)
         + 0.10·style(in, c)                         // polite 같음 +0.5, question 같음 +0.3, len 인접 +0.2
```
- 태그 충돌 벌점: 입력이 `refuse`인데 후보가 `agree`만 있으면 −0.25 (반대 극성 쌍: refuse↔agree, honest↔passive, assert↔passive).
- 입력 `action`=true 이면 서술형 선택지("…한다")의 `textGrams` 가중치를 0.40→0.50 으로 올린다(행동을 서술한 입력은 행동 선택지를 찾는 중).
- `require` 로 **잠긴 선택지도 점수는 매긴다**(1위가 잠긴 것이면 "아직 못 하는 말"로 안내해야 하므로). 자동 확정만 막는다.

### 1.6 신뢰도·동점 처리
| 조건 | 결정 |
|---|---|
| `s1 ≥ 0.38` 이고 `s1 − s2 ≥ 0.12` 이고 1위가 일반 선택지 | **자동 확정** (`MatchResult.auto`) |
| 위 조건이지만 1위가 `chance`·`minigame`·잠김 | **확인 한 번** (§3.3) |
| `0.18 ≤ s1 < 0.38` 또는 `s1 − s2 < 0.12` | **"이런 뜻이에요?" 피커**, 후보를 점수순으로, 상위 1~2개 강조 |
| `s1 < 0.18` | 피커, 문구 "잘 못 알아들었어요 — 어느 쪽에 가까워요?" 강조 없음 |
동점(차 < 0.02)은 항상 피커. 무작위 선택은 **절대** 없다. 임계값은 `FreeInputMatcher.thresholds` 상수로 두고 §1.7 픽스처로 조정한다.

## 2. 저작 방식 — 하이브리드

**자동 유도가 기본, 손보정은 예외.** 447개를 손으로 다는 건 안 한다. 대신:
1. 런타임 자동 서명(§1.4)이 모든 선택지에 붙는다. 저작 비용 0.
2. 선택적 JSON 필드 `intent` (Choice 에 추가, 없으면 빈 목록 — 스키마 호환):
   ```json
   { "text": "하나만", "intent": ["하나만 눌러", "하트 하나", "한 개만", "적당히"], "effects": {...} }
   ```
   `intent` 문자열은 **그 선택지의 `textGrams`·`tags` 에 합쳐진다**(플레이어가 칠 법한 짧은 표현을 그대로 적는다, 태그 이름을 적는 게 아니다).
3. `tool/intent_report.py` — 분리도 보고서. 이벤트마다 §1.5 점수 함수를 파이썬으로 같게 구현해(픽스처로 Dart 와 동치 검증) 다음을 판정한다:
   - **자기 회수**: 각 선택지 문구 자체를 입력으로 넣었을 때 1위가 자기 자신인가(아니면 즉시 FAIL).
   - **쌍 유사도**: 보이는 선택지 두 개의 서명 유사도(`jaccard(tags)`·`dice(grams)` 합) > 0.55 → LOW.
   - **빈 서명**: 본문 2-gram ≤ 2 개이고 태그 0개 → EMPTY (예: "하나만", "물어본다").
   - 출력: `tool/sim_out/intent_report.md` — LOW/EMPTY 를 이벤트 id·선택지 index·이유·제안 표현(반응 줄에서 뽑은 명사) 순으로. 예상 60~90개 이벤트(전체의 15~20%)에 `intent` 를 단다. 하나에 3분 → 반나절.
4. `test/free_input_test.dart` 가 픽스처와 함께 **자기 회수 100%** 를 전 이벤트에 대해 검사한다(reply_coverage_test 와 같은 파일 목록 사용). 새 이벤트를 추가하면 여기서 걸린다.

## 3. UX 흐름

### 3.1 배치
- 선택지 버튼은 **지금 그대로** 남는다(제거·축소 아님). 그 아래 한 줄 입력창 `직접 말하기…` + 보내기 아이콘. 힌트 버튼(광고)은 입력창 아래.
- 입력창에 포커스가 오면 키보드가 올라오고 버튼들은 **가로 스크롤 칩 한 줄**로 접힌다(문구 14자까지 + …). 칩을 누르면 버튼과 같은 경로(`_pick`). 플레이어가 무엇을 칠지 감을 잡게 후보를 계속 보여 주는 것이 핵심이다 — 빈 입력창은 백지 공포다.
- 전화(`format: call`) 화면에서는 입력창 대신 "말하기" 버튼 하나가 뜨고 누르면 같은 입력창이 시트로 올라온다(통화 UI 는 좁다).
- 하드코어 플래그·동작 줄이기 설정과 무관하게 항상 보인다. 설정에 `자유 입력 끄기` 토글(기본 켬)만 둔다.

### 3.2 보내기 → 결과
1. `FreeInputMatcher.match` (동기, 이벤트당 서명 캐시 후 1ms 대).
2. **자동 확정**: `onPicked(입력문)` → `c.choose(index)`. 내 말풍선 = 친 문장. 반응은 기존 outcome. 결과 패널 첫 줄에 작은 회색 캡션
   `→ "선택지 원문" 으로 알아들었어요` 를 넣는다. 몰입을 조금 깎지만 오매핑을 플레이어가 **스스로 알아채는 유일한 창**이라 필수.
3. **피커**: 바텀시트 `이런 뜻이에요?` — 친 문장을 위에 인용, 아래에 보이는 선택지 버튼(점수순, 상위 1~2개 `recommended` 스타일). 고르면 2번과 같되 내 말풍선은 여전히 친 문장. `다시 쓰기` 로 입력창에 문장 유지한 채 복귀.
4. **잠긴 선택지가 1위**: 확정하지 않는다. 입력창 위에 narr 톤 한 줄 `아직 그 말은 안 나온다. (눈치 40 필요)` (`ChoiceView.reason` 재사용) 를 띄우고 문장은 남긴다. 되돌리기 소모 없음, 이벤트 진행 없음. 이걸로 "왜 안 되지"가 아니라 "성장하면 할 수 있는 말"이 된다.
5. **`chance` / `minigame` 이 1위**: 확인 칩 한 번 — `"선택지 원문" (75%) [이대로] [다른 뜻]` / 미니게임은 `[게임 시작]`. 미니게임은 실력 판정이라 문장으로 건너뛸 수 없다. 확인 뒤엔 `_pick(index)` 와 동일 경로(미니게임 → `choose(minigameSuccess:…)`). 말풍선은 친 문장.

### 3.3 무료 되돌리기 (이벤트당 1회, 광고 없음)
- 조건: 이 이벤트의 선택이 **자유 입력 자동 확정**으로 이루어졌고(`c.lastChoiceSource == ChoiceSource.freeText`), 아직 되돌리기를 안 썼고, 하드코어 아님. 피커·확인 칩을 거쳐 고른 것은 플레이어가 확인한 셈이므로 무료 되돌리기 대상이 아니다(기존 광고 되돌리기 규칙 그대로).
- 결과 패널 버튼 `그런 뜻 아니었어요` → `undoChoice()` 그대로(스냅샷 복원·큐 정리·`undoUsedThisEvent=true`) + 입력창에 문장 복원 + **이번엔 피커를 강제**(자동 확정 재시도 금지 → 되돌리기 루프 없음). 광고 되돌리기와 합쳐 이벤트당 1회라 "공짜로 결과 엿보기"는 한 번뿐이다.
- 기존 `canOfferUndo`(호감 하락·실패 때만)는 손대지 않고 `canOfferFreeUndo` 를 따로 둔다. 무료 되돌리기는 결과와 무관하게 뜬다 — 문제는 결과가 아니라 **이해**이므로.

### 3.4 저장·표시 (추가만, 기존 세이브 그대로 읽힘)
- `GameState.freeInputs: List<FreeInputEntry>` `{e: eventId, i: choiceIndex, t: 원문(≤80자), d: day, a: auto?1:0}` — 최근 30개만 유지. `toJson` 에 `freeInputs` 키 추가, `fromJson` 은 키 없으면 빈 목록. `save_migration_test` 에 케이스 하나 추가.
- 컨트롤러: `String? lastPlayerText`(메모리) + `ChoiceSource lastChoiceSource`. `choose(index, {playerText, source})` 로 인자만 늘린다. `_picked` 는 지금처럼 화면 상태로 두되 원천을 `lastPlayerText` 로 바꾸면 **앱을 껐다 켜도 내 말풍선이 친 문장으로 복원**된다(지금은 선택지 원문도 복원 안 됨 — 개선).
- 결과 패널·통화 자막·정산: 내 말풍선은 친 문장. 정산 화면에 `오늘 내가 한 말` 카드(당일 `freeInputs` 최대 3줄, 옆에 작은 글씨로 매핑된 선택지). 앨범·엔딩 텍스트는 손대지 않는다.

목표치(출시 후 2주): 자유 입력 사용자 ≥ 30%, 자동 확정률 45~60%, 피커 1위 일치 ≥ 75%, 자동 확정 후 되돌리기 ≤ 8%, 이벤트별 되돌리기 ≥ 20%인 이벤트 → `intent` 보정 대상.

**LLM 트랙용 학습 데이터**: 원문은 Firebase 로 가지 않는다(정책). 원문↔선택지 쌍은 기기 세이브 `freeInputs` 에만 남는다. 풀 LLM 트랙에서 필요하면
설정에 **명시 옵트인** `내가 쓴 말을 개선에 제공` 을 넣고 별도 엔드포인트로 보내는 것을 그 트랙에서 설계한다. 지금은 위 구조 지표만으로
"어느 이벤트에서 어떤 스타일의 입력이 어떤 확신도로 어디에 붙었나"를 모은다 — 이것만으로 임계값·사전·`intent` 보정은 충분하다.
