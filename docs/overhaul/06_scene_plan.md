# 06. 장면 계획 — 어떤 장면에 그림이 붙고, 왜 (2026-09-23)

> OVERHAUL_PLAN.md §2D 의 "무엇을 그릴지" 답. 프롬프트는 쓰지 않는다(Image Prompt Engineer 가 `docs/SCENE_PROMPTS.md` 로 이어서).
> 근거: CAST_BIBLE.md, MOMENTS_SPEC.md, PORTRAIT_PROMPTS.md §1–2, `assets/story/*.json`(이벤트 447, 모먼트 30+24, 엔딩 60), `lib/ui/photo_card.dart`.
> 테스터 피드백 "텍스트만 나와서 집중이 안 된다" 에 대한 답은 **"그림을 많이" 가 아니라 "하루에 한 번, 기억에 남는 순간에"** 다.

## 0. 원칙 세 줄

1. **그림은 희소해야 힘이 있다.** 하루 4개 이벤트 중 그림이 붙는 건 최대 1개(모먼트)여야 "오늘은 뭐지" 가 생긴다. 447개 전부는 오히려 벽지가 된다.
2. **얼굴은 초상화 한 장에서만.** 삽화·사진에 캐릭터가 나오면 뒷모습·옆모습·손·소품까지만. 생성 이미지마다 얼굴이 달라지는 위험(PORTRAIT_PROMPTS 관찰 로그 #4)을 원천 차단하고, 메신저 게임답게 "상대가 보낸 사진" 의 상상 여지를 남긴다. 얼굴이 필요한 건 스티커뿐이고, 스티커는 초상화에서 파생한다.
3. **주인공은 성별 중립(CAST_BIBLE §0.3).** "나" 가 화면에 나오면 손·뒷모습·실루엣만, 머리 길이·옷에서 성별 단서 없음.

## 1. 시각 체계 — 이미지 3종

## 3. 프롬프트 엔지니어가 지킬 일관성 규칙

1. **화풍 잠금.** PORTRAIT_PROMPTS §2 라인업의 화풍 문장을 **모든 프롬프트 맨 끝에 그대로**: "깔끔한 반실사 디지털 일러스트, 가는 외곽선, 부드러운 셀 채색, 따뜻하고 부드러운 조명". 사진 메시지도 실사(포토리얼)로 가지 않는다 — "일러스트로 그린 폰 사진" 이며 폰카 느낌은 구도(흔들림·역광·비뚤어진 프레임·플래시 반사)로만 낸다. 초상화(웹툰풍)와 사진(실사)이 한 화면에 섞이면 세계가 둘로 갈라진다.
2. **글자 0.** 간판·칠판·메모장·영수증·달력·계획표·게임 UI·폰 화면 — 이 게임의 소품은 거의 글자인데, 생성 이미지의 글자는 반드시 깨진다. 규칙: 글자가 있어야 할 자리는 **읽을 수 없는 획·낙서·빈 칸·동그라미**로 두고 의미는 `caption` 과 대사가 준다. 숫자도 금지(달력 날짜·체중·시계). 이름표·번호·워터마크·로고 금지(이미 라인업 규칙).
3. **얼굴은 스티커에서만, 스티커는 초상화에서.** 삽화·사진·엔딩에 12명이 나오면 뒷모습·옆모습(코까지)·손·소품까지. 스티커는 해당 캐릭터의 `assets/portraits/<id>.jpg` 를 **첨부한 같은 대화에서** "같은 인물, 표정과 손만 바꿈, 머리·옷·액세서리 유지" 로 4~5장을 연속 생성한다(관찰 로그 #4). 라인업 교훈대로 한 캐릭터의 4감정을 **한 장에 2×2 로** 먼저 뽑고 잘라 쓰면 얼굴이 흔들리지 않는다.
4. **정체성 앵커(얼굴 없이 알아보게).** 삽화·사진에 캐릭터의 존재를 남길 때 쓰는 소품 — 서연 허리 흑발·차콜 카디건 / 다은 볼펜 반묶음·앞치마·연필 흑연 / 지우 네이비 재킷·진주 귀걸이·서류 / 소희 흰 헤드셋·연회색 후드·목캔디 / 예은 땋은 적갈색 머리·세이지 카디건 / 유나 하이 포니·비취 트레이닝·형광 머리끈 / 정우 원형 안경·칼각 셔츠·열쇠 꾸러미 / 하늘 데님 앞치마·체크 행주 / 승현 흰 가운·청진기·강아지 털 / 민재 네이비 후드·헤드셋·모니터 불빛 / 건우 베이지 카디건·분필 가루·스티커 붙은 가방 / 도윤 차콜 트레이닝·흰 수건·버즈컷 뒷모습. **PORTRAIT_PROMPTS §1.2·1.4 표와 다른 소품을 새로 만들지 않는다.**
5. **주인공 중립.** "나" 는 손·뒷모습·실루엣. 머리는 귀 덮는 중간 길이, 옷은 무채색 후드·셔츠, 손톱·액세서리 없음. 주인공 이름·성별을 암시하는 소품 금지.
6. **12+ 등급(CAST_BIBLE §0.3, PORTRAIT_PROMPTS §1.6).** 술잔·병·담배 없음(서연 태그의 '술', m07 뒤풀이는 음료 컵으로). 노출·몸매 강조 없음 — 헬스장 장면도 얼굴 없는 기구·수건·거울. 어린 시절 사진(P08·E11)은 **빛바램 + 원거리 + 얼굴 흐림**으로만, 현재 캐릭터의 얼굴과 이어지지 않게. 실존 브랜드·게임·앱 UI 금지(폰 화면은 빛만). 유나 대회 시절·체중 숫자 없음.
7. **색은 캐릭터 강조색을 주조로.** `lib/ui/design_system.dart` `characterAccents`(CAST_BIBLE §3) 의 base 색을 그 캐릭터 장면의 빛·소품에 한 번 넣는다(서연 연보라 야경, 하늘 청록 형광등, 다은 자두빛 저녁…). 카드 테두리·말풍선과 그림이 이어진다. 공용 사진(Pi)은 중립색으로 두고 코드가 강조색 틴트를 얹는다.
8. **다크 모드 한 장으로.** 그림은 한 벌만. 흰 배경 큰 면적 금지(다크에서 눈부심), 중간 명도 위주. 코드가 다크에서 12% 어둡게 얹는다.
9. **안전 영역.** 3:2 삽화는 넓은 화면에서 위아래 10% 가 잘릴 수 있다 — 핵심 소품은 중앙 80% 안. 사진 4:3 은 폴라로이드 안에서 잘리지 않는다. 스티커는 투명 배경, 캐릭터가 캔버스 85% 를 채우고 바닥 그림자 없음.
10. **파일.** webp, 삽화·엔딩 1200×800, 사진 800×600, 스티커 384×384(알파). 파일명은 §4 규약 그대로, 소문자·언더스코어.

| 사진 메시지 | `photo.image` (선택) | `assets/photos/<icon>.webp`(공용) | 지금의 `PhotoScene` 아이콘 그림. `caption`·스크린리더 라벨 불변 |
| 스티커 | `sticker` on `Line` (string, 선택) | `assets/stickers/<char>_<emotion>.webp`. `<char>` 는 이벤트 `character`; 없으면(태현 등) 무시. 그룹 대화용 `{"char":"seoyeon","emotion":"joy"}` 객체형도 허용 | 아무것도 그리지 않음(빈 줄도 없음) |

- **등록 방식은 `PortraitRegistry` 와 동일**: 시작 시 `AssetManifest` 를 한 번 읽어 `assets/scenes/`·`photos/`·`stickers/`·`endings/` 를 캐시(`SceneRegistry`). 파일만 넣고 재빌드하면 뜬다. 필드는 공유·예외용(예: `m03`/`m03_m`, `m_mbti_chat_f`/`_m` 가 한 장을 같이 씀).
- **검증기**: `image`/`photo.image` 는 `assets/` 로 시작하는 문자열만, **존재는 검사하지 않는다**(테스트·CI 는 그림 없이 돈다). `sticker` 는 감정 id 화이트리스트(`joy sulk shy surprise` + 캐릭터별 5번째: `daeun_blank`, `sohee_call`, `jeongwoo_haha`, `seunghyun_sure`).
- **구현 확정(2026-09-24, 4단계)**: `sticker` 값은 위 표의 `<char>_<emotion>` 조합이 아니라 **파일 이름 그대로**다 — `"sticker": "seoyeon_shy"`. 5번째 스티커 id(`daeun_blank`)가 이미 같은 꼴이라 규약이 하나로 합쳐지고, 그룹 대화에서도 이벤트 `character` 와 무관하게 화자를 적을 수 있다(객체형은 두지 않았다). 감정 4종의 철자는 `sulk`·`surprise`(파일명과 같다). 엔딩은 `image` → 엔딩 id → 캐릭터 id → `common_<tier>` 순, `image` 가 가리킨 파일이 없으면 규약 경로로 되돌아간다.
- **세이브 호환**: 세이브에는 아무것도 추가하지 않는다(그림은 렌더링만). `save_migration_test.dart` 영향 없음.
- **pubspec**: `assets/scenes/`, `assets/photos/`, `assets/stickers/`, `assets/endings/` 를 `.gitkeep` 과 함께 등록. 예상 번들 증가 ≈ 11MB(1차 113장).
- **접근성**: 삽화 카드 `Semantics(image, label: "<이벤트 title> 장면")`, 스티커 `label: "<이름> 스티커: 기쁨"`. 동작 줄이기면 켄번즈·팝인 정지. 사진 카드 라벨은 지금대로 `사진: <caption>`.

## 5. 스티커 배치 (2026-09-24, 4단계 후속)

§2.2 의 52장을 실제 대사에 붙였다. 배치는 `tool/add_stickers.py` 의 `PLACEMENTS` 표 하나에 들어 있고,
스크립트를 다시 돌리면 같은 결과가 나온다(손으로 JSON 을 고치지 않는다). 늘리거나 옮길 때도 표만 고친다.

### 5.1 밀도 — 447개 중 87개

| | 값 |
|---|---|
| 스티커가 붙은 이벤트 | **87 / 447 (≈ 5개 중 1개)** |
| 이벤트당 최대 | 1개 (스크립트가 강제) |
| 캐릭터당 | 7~8개 |
| 쓰인 스티커 id | 52 / 52 (전부 한 번 이상) |
| 감정별 | 기쁨 23 · 삐짐 18 · 부끄 21 · 놀람 21 · 5번째 4 |

§0 원칙 1("그림은 희소해야 힘이 있다")과 §1("하루 최대 1장")을 스티커에도 그대로 적용했다.
하루에 이벤트가 4개씩 도니까 **5개 중 1개**면 플레이어 체감은 "이틀에 한 번쯤 상대 얼굴이 뜬다" 다.
스티커는 삽화보다 작고(120pt) 말풍선 흐름을 끊지 않아 삽화(하루 1장)보다 조금 촘촘해도 벽지가 되지 않지만,
그 이상 늘리면 "이모티콘 남발하는 사람" 이 되어 캐릭터가 싸구려로 보인다. 60~110 구간의 아래쪽을 골랐다.

**루트 안에서의 분포**(캐릭터당 7~8개, 루트 이벤트 16 + 모먼트 3~5 + 메인/일상 몇 개 기준):
루트 1개당 4~5개 + 모먼트 2~3개. 첫 접촉(`r00`)에 거의 항상 한 장을 둬서 "이 캐릭터는 스티커를 쓴다" 를
일찍 알리고, 그다음부터는 감정이 꺾이는 지점에만 띄엄띄엄 놓았다.

### 5.2 고르는 기준 (작가용)

1. **글만으로는 모자란 줄에만.** 한 단어 답장(`"네."` `"헐"` `"…"` `"ㅋㅋ"`), 얼버무리는 딴소리,
   진짜 놀란 반응. 글이 이미 감정을 다 말하는 줄("나 지금 얼굴 빨개진 거…")에는 **안 붙인다** — 중복이다.
   붙일 거면 그 앞의 `"…"` 에 붙여서 스티커가 먼저 말하게 한다(`seoyeon_r09`).
2. **반응이 우선.** `choices[].reply` / `critReply` / `failReply` 쪽이 `lines[]` 보다 낫다.
   플레이어가 고른 결과에 상대가 표정으로 답하는 게 스티커의 일이다. 87개 중 83개가 반응 줄이다.
3. **`lines[]` 에 붙인 넷은 전부 "그 캐릭터를 한 컷으로 설명하는 줄"** 이다:
   `sohee_r01` 첫 샷콜, `sohee_r06` 목 나간 날, `jeongwoo_r03` "취소가 안 되네. 하하.",
   `jeongwoo_r10` 정우의 첫 `ㅋㅋ`.
4. **화자 == 스티커 주인.** 줄에 `name` 이 있으면 그 이름이, 없으면 이벤트 `character` 가 기준이다.
   조연(태현·준호·신입·점장)이 말하는 줄에는 스티커가 없다. 스크립트가 검사한다.
5. **`photo` 가 붙은 줄은 건너뛴다.** 창이 이미 찼다.
6. **감정의 정점은 비워 둔다.** `mo_jiwoo_call_eve`(기일 전날), `geonwoo_r15`("…좋아해") 처럼
   대사 하나로 끝나야 하는 장면에는 일부러 아무것도 안 붙였다. 스티커가 무게를 깎는다.

### 5.3 5번째 스티커 4장을 쓴 자리

§2.2 에서 "4감정으로는 표현이 안 되는 시그니처" 라고 적은 넷이라, 다른 데 흩뿌리지 않고 **그 캐릭터의
시그니처가 성립하는 딱 한 장면**에만 썼다.

| 스티커 | 자리 | 왜 거기인가 |
|---|---|---|
| `daeun_blank` | `daeun_r00` 선택지 0 `reply[0]` — `"네."` | 다은의 첫 답장. 바로 다음 줄이 나레이션 "그게 끝인 줄 알았다" 다. 무표정 스티커가 그 정적을 그림으로 받아 준다. 다은의 기본값을 루트 첫 이벤트에서 선언하는 자리 |
| `sohee_call` | `sohee_r01` `lines[1]` — `"드래곤 ㄱㄱ!! 탑 빠져!"` | 소희 목소리를 처음 듣는 줄. 샷콜 톤은 "신난 외침"(`joy`)과 다른 **집중**이고, 그 차이를 여기서 한 번 보여 줘야 이후의 `sohee_joy`·`sohee_sulk` 가 구분된다 |

| `seunghyun_sure` | `seunghyun_r13` 선택지 2 `reply[0]` — `"떠보신 거면, 확실하게 말할게요. 좋아해요."` | §2.2 가 "좋아해요 용" 이라고 지정한 용도 그대로. 떠보는 문자에 정면으로 되받는 유일한 장면이고, 승현 루트에서 "확실히" 가 고백으로 바뀌는 지점 |

### 5.4 스크립트와 검증

```sh
python3 tool/add_stickers.py --check   # 검증만 (파일 안 씀)
python3 tool/add_stickers.py           # 적용
```

스크립트가 **직접** 막는 것(검증기가 안 보는 것들이다):

- 이벤트당 2개 이상
- `me`/`narr`/`sys` 줄, 이미 `photo` 나 `sticker` 가 있는 줄
- 화자와 스티커 주인이 다른 경우 (§5.2-4)
- 표에 적은 대사 앞부분이 실제 JSON 과 다를 때(이벤트가 리라이트되면 여기서 멈춘다)
- 52개 중 한 번도 안 쓰인 id 가 있을 때

`story_repository.dart` `_checkLines` 는 id 화이트리스트만 본다 — **캐릭터가 맞는지는 검사하지 않으므로**
(`Sticker.isValid` 는 접미사만 본다) 위 검사는 스크립트 쪽에 있어야 한다.

JSON 은 `json.dumps(..., ensure_ascii=False, indent=1)` 로 다시 쓴다. 16개 파일 전부 원본과 바이트가
같은 것을 확인했으므로 스티커 줄 외에는 diff 가 나지 않는다. 문자열로만 적혀 있던 반응 줄은
스티커를 붙이는 그 자리만 `{"who": "them", "text": …, "sticker": …}` 로 바뀐다(나머지 항목은 문자열 그대로).
`sticker` 키는 줄의 맨 뒤 — `models.dart` `Line` 의 필드 순서와 같다.

에셋이 아직 없어도 화면은 지금과 똑같다(`SceneImages.forSticker` 가 파일을 못 찾으면 아무것도 안 그린다).
`assets/stickers/*.webp` 52장이 들어오는 순간 전부 켜진다.
